# 任务交接 · Offerbiu 竞品内页深度分析（TASK-COMPETITOR-ANALYSIS）

> **给具备多模态视觉能力的智能体的任务。**
> Codex（主智能体）无法可靠查看用户提供的 Offerbiu 截图（analyze_image 被内容过滤器拦截，且无法读 URL 图片）。本任务需要能**直接看截图并描述内容**的智能体，对 Offerbiu 内页做深度功能分析，产出结构化结论供 Codex 更新设计文档。
>
> **本文件自包含**——包含分析目标、截图清单、产出格式要求。

## 一、任务目标

深入分析竞品 Offerbiu（offerbiu.com，大学生秋招投递管理工具）的**真实产品内页**，提取其完整功能矩阵、交互模式、数据字段，输出**结构化分析报告**。

Codex 已基于首页文案整理了初步对标文档（`docs/research/competitor-offerbiu.md`），但内页需登录，无法抓取。本任务通过截图分析补全内页细节。

---

## 二、背景：已知信息与盲区

### Codex 已知（来自首页）
- Offerbiu 定位：大学生秋招投递管理工具
- 核心主张："四位一体"——岗位 + 简历版本 + JD 分析 + AI 匹配
- 已上线运营，Web 应用

### Codex 识别的 3 个盲区（我们没设计的功能）
1. **简历工作区**（多版本简历管理）
2. **AI 匹配**（JD 关键词 + 匹配度评分）
3. **简历优化**（AI 改写建议）

### 我们的产品（JobPulse）已有的功能（用于对比）
- 多平台自动采集（BOSS/拉勾/牛客/实习僧/官网）
- 9 状态投递管理 + 修正机制
- 数据看板（KPI/漏斗/趋势）
- 邮件 AI 解析
- 详见 `docs/product/PRD.md`

## 四、分析方法

1. **逐张看图**，对每张截图回答第 5 节的问题
2. **不要臆测**——只描述截图中**实际可见**的内容
3. **特别关注**：Offerbiu 有而我们没有的功能（简历/AI 匹配/优化）
4. **记录数据字段**：所有可见的表单字段、列表列、状态值
5. **记录交互线索**：按钮、标签页、下拉菜单、模态框入口

## 五、每张截图要回答的问题

对每张截图，回答以下 8 个问题：

```
截图 #N：[页面名称]

1. 页面类型：这是什么页面？（工作台/投递列表/投递详情/简历/AI匹配/定价/其他）
2. 布局结构：整体布局？（左栏导航+主区 / 顶部Tab+列表 / 卡片网格 / 其他）
   - 左侧导航有哪些菜单项？（逐个列出）
   - 顶部导航有什么？（logo/搜索/用户菜单/通知）
3. 功能模块：主内容区有哪些区块/卡片/模块？（逐个列出标题和内容）
4. 数据字段：可见哪些数据字段？（如：公司名、岗位、状态、日期、匹配度、简历版本等）
5. 状态/标签：有没有状态标签？有哪些值？（如：已投递/笔试中/面试中/Offer）
6. AI 功能：有没有 AI 相关的入口或展示？（JD分析/匹配度/优化建议/智能推荐）
7. 交互元素：有哪些按钮/Tab/下拉/可点击元素？分别是什么？
8. 与 JobPulse 的差异：这页有什么是我们没有的？有什么我们做得更好的？
```
