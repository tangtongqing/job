# TASK-014 · impeccable shape · 岗位列表 + 详情设计简报

## 背景与目标

TASK-013 看板首页设计简报已完成（v2）。本任务执行 `impeccable shape jobs`——为**岗位列表 + 岗位详情**两个页面产出设计简报。

岗位列表是用户**最高频使用**的页面（浏览/筛选/收藏），岗位详情是**投递决策**的依据。两者紧密关联，合并为一个 shape 任务。

**目标**：产出岗位列表 + 详情的完整设计简报，覆盖信息架构、布局、组件、交互、状态，可直接指导 TASK-016 craft。

## 实现要求

### 一、岗位列表设计简报

#### 1. 任务与用户上下文
- 谁（P1 高频投递者，每天浏览）
- 核心问题：3 个
  1. "有没有我想要的新岗位？"
  2. "这个岗位适不适合我（应届/实习/硬条件）？"
  3. "这个岗位我收藏/投递过没？"
- 核心任务路径

#### 2. 信息架构
**列表项内容**（每个岗位卡片/行）：
- 必显示：公司名、岗位名、地点、薪资、来源平台、发布时间
- 状态标识：有效性（有效/失效）、应届/实习标签、收藏/待投递/已投递标识
- 快捷操作：收藏、标记待投递、查看详情

**筛选区**（呼应 F-A.3）：
- 关键词搜索
- 筛选：地点 / 公司 / 薪资范围 / 应届标签 / 来源平台 / 岗位方向（job_category）
- 硬条件筛选（呼应 JS-20）：毕业年份 / 实习天数 / 实习周期
- 排序：发布时间 / 薪资 / 采集时间
- **筛选默认收起，高级筛选按需展开**（呼应 DESIGN.md §1.1 效率优先）

**列表布局**：
- 表格视图 vs 卡片视图（建议表格，信息密度高，呼应 product register）
- 分页：每页 20 条

#### 3. 布局方案（ASCII 线框图）
桌面端（≥1024px）线框图，标注筛选区/列表区/分页区的位置与尺寸。

#### 4. 组件清单
- Table（shadcn/ui）—— 列表
- Input + Select + Checkbox —— 筛选
- Badge —— 状态标签（应届/实习/有效性/收藏）
- Button —— 快捷操作
- Pagination —— 分页
- Skeleton —— 加载态

#### 5. 交互设计
- 筛选条件变更 → URL query 同步（可分享/刷新保持）
- 行点击 → 跳转详情
- 收藏/待投递 → 乐观更新（TanStack Query）
- 批量操作（呼应 F-C.5）→ 多选 + 批量收藏/待投递

#### 6. 状态设计（重点）
- **空状态**：无岗位（"暂无符合条件的岗位，建议放宽条件"）/ 无收藏（引导去列表）
- **加载状态**：Skeleton 表格行
- **错误状态**：错误 + 重试
- **部分加载**：筛选时列表区单独 loading，筛选区不闪

### 二、岗位详情设计简报

#### 1. 任务与用户上下文
- 谁（投递决策中的用户）
- 核心问题：3 个
  1. "这个岗位具体要求什么？"
  2. "这个岗位还有效吗？什么时候截止？"
  3. "我要怎么投递？投递链接在哪？"

#### 2. 信息架构
**详情页区块**：
- 头部：公司名 + 岗位名 + 地点 + 薪资 + 状态标签（应届/实习/有效性）
- 关键信息卡：发布时间 / 截止时间 / 来源平台 / 最后核验时间
- 岗位描述（JD）：完整文本
- 招聘要求（requirement）：结构化展示（呼应 F-A.4 v3，与 JD 分离）
  - 学历要求 / 经验要求 / 毕业年份 / 其他硬条件
- 投递区：投递链接（外链）+ 来源标注 + "去投递"按钮
- 操作区：收藏 / 标记待投递 / 直接投递（创建 Application）

#### 3. 布局方案（ASCII 线框图）
标注各区块位置。考虑：详情页是否需要侧边栏（相关岗位推荐）？Demo 阶段建议**不要**相关推荐（避免范围蔓延，且无数据支撑）。

#### 4. 组件清单
- Card / Badge / Button / Alert（DDL 临近提醒）/ Skeleton

#### 5. 交互设计
- "去投递"→ 新窗口打开外链（不离开本站）
- "收藏/待投递"→ 乐观更新
- "直接投递"→ 创建 Application，跳转投递管理或弹窗确认
- DDL 临近（≤3天）→ Alert 高亮提醒

#### 6. 状态设计
- 加载态：Skeleton（头部 + 内容区块独立骨架）
- 错误态：岗位不存在（404）/ 加载失败
- 边界态：岗位已失效（显示但置灰 + 提示"该岗位可能已关闭"）

### 三、收藏/待投递列表（/saved，Tabs 切换）

呼应 TASK-012 v2 的合并决策（/favorites + /to-apply → /saved + Tabs）。
简要说明：复用岗位列表组件，Tabs 切换收藏/待投递，支持一键升级（收藏→待投递→投递）。

### 四、数据契约映射
- 列表 → `GET /jobs`（含筛选参数）
- 详情 → `GET /jobs/{id}`
- 收藏 → `POST /jobs/{id}/favorite`
- 待投递 → `POST /jobs/{id}/to-apply`
- 有效性 → `POST /jobs/{id}/verify`
