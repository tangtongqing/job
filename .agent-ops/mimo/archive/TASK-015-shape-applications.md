## 实现要求

### 一、投递列表设计简报

#### 1. 任务与用户上下文
- 谁（P1 高频投递者，管理 20-50 个投递）
- 核心问题：3 个
  1. "我的每个投递现在到哪一步了？"
  2. "哪些需要我跟进（DDL/无回应/待办）？"
  3. "我的整体转化怎么样？"（链接到看板）

#### 2. 信息架构
**列表项内容**：
- 公司名、岗位名、当前状态 Badge（9 状态语义色）、投递时间、最后更新时间
- 快捷操作：状态流转（下一状态）、纠错、查看时间线

**状态筛选**（呼应状态机）：
- 按状态分组：进行中（applied/test/interviewing/offer_pending）/ 已结束（5 终态）
- Tab 切换：全部 / 进行中 / 已结束 / 需关注（DDL 临近 + 无回应）

**列表布局**：表格视图（与岗位列表一致）

#### 3. 状态流转交互（核心，最复杂）
这是本产品的灵魂。设计要点：
- **快捷流转**：每个投递行的状态 Badge 可点击，弹出"下一状态"快捷菜单（只显示合法的下一状态，基于状态机）
- **状态机可视化**：用户点击状态时，能看到"当前状态 + 可流转的下一状态"
- **纠错入口**：每个投递有"纠错"操作（可回退到任意历史状态，需填纠错原因）
- **批量流转**：呼应 TASK-008 v2 的 batch-transition（多选 + 批量标记状态）

#### 4. 布局方案（ASCII 线框图）
标注列表 + 状态筛选 Tab + 快捷流转菜单。

#### 5. 组件清单
- Table / Tabs / Badge / DropdownMenu（状态快捷菜单）/ Dialog（纠错）/ Skeleton

#### 6. 交互设计
- 状态 Badge 点击 → 快捷流转菜单
- 行点击 → 跳转详情/时间线
- 纠错 → Dialog（选目标状态 + 填原因）
- 批量 → 多选 + 批量流转

#### 7. 状态设计
- 空态：无投递（引导去岗位列表）
- 加载态：Skeleton
- 错误态：重试

### 二、投递详情 + 事件时间线设计简报

#### 1. 信息架构
- 头部：公司 + 岗位 + 当前状态 Badge + 投递时间
- **事件时间线**（核心）：垂直展示所有 ApplicationEvent（status_change/interview/test/...）
  - 每个事件：时间 + 类型 + from→to + 备注

- 操作区：状态流转 + 纠错 + 编辑备注

- 待办事件（未来的笔试/面试）如何展示（高亮 + 倒计时）

### 三、AI 解析设计简报（F-C.5，亮点）

#### 1. 入口设计
- 哪里触发 AI 解析？（投递列表的快捷按钮 / 顶部全局入口 / 详情页）
- 建议多个入口（降低使用门槛）

#### 2. 解析交互流程
呼应 ai-parser-module.md v2 的三级降级 + 用户确认：
```
用户粘贴邮件文本
    ↓
调用 POST /applications/parse-email
    ↓
返回结果（parsed=true/false, confidence, degraded）
    ↓
展示建议卡片：公司/岗位/建议状态/置信度/匹配的投递
    ↓
用户确认 → 调用 transition API
用户修改 → 修改后确认
用户取消 → 不执行
```

#### 3. 三级降级的 UI 体现
- L1 LLM 高置信度：绿色建议卡 + "确认"
- L2 正则降级：黄色建议卡 + "降级解析"标签 + "确认"
- L3 全失败：提示"无法自动解析，请手动选择"

#### 4. 隐私提示（呼应 TASK-011 v2 的 AI 邮件隐私风险）
- 输入框上方提示："您粘贴的内容将发送给 AI 解析，请勿粘贴含敏感薪资的完整邮件"
