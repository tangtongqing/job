# Codex ↔ Mimo Code 协作规范

> 本文档定义主智能体（Codex）与执行智能体（Mimo Code）的协作方式。
> 默认协作模式：**文件交接（File Handoff）**，不通过终端附着、后台自动化或服务器控制。

---

## 1. 目录约定

```
.agent-ops/
  mimo/
    inbox/      # Codex 写任务简报（Mimo 只读最新一份）
    outbox/     # Mimo 写执行结果
    archive/    # 已验收完成的任务归档
```

## 2. 任务简报格式（Codex → Mimo）

每个任务写入 `.agent-ops/mimo/inbox/TASK-NNN-<short-name>.md`，必须包含：

```markdown
# TASK-NNN · <任务标题>

## 背景与目标
<为什么做这个任务，要达成什么>

## 允许读取的路径
- ...

## 允许修改的路径
- ...

## 禁止操作
- 不做无关重构
- 不引入未批准的外部服务 / 凭证
- 不超出授权范围修改文件

## 实现要求
1. ...
2. ...

## 验证命令
- `命令` → 期望结果

## 结果文件路径
.agent-ops/mimo/outbox/TASK-NNN-result.md

## 结果格式（Mimo 必须填写）
- 摘要
- 修改的文件清单
- 关键实现点
- 执行的命令与结果
- 未解决的问题
- 需要 Codex 判断的风险
```

## 3. Mimo 职责

1. 只读 `inbox/` 中**最新**的任务简报（除非任务另有说明）
2. 只在授权的文件与行为范围内工作
3. 不做无关重构、不引入隐藏依赖、不调用真实后端 / 凭证 / 未批准服务
4. 结果写入任务指定的 `outbox/` 文件
5. 遇到阻塞、测试失败、不确定、权限或安全问题时**报告**，不猜测

## 4. Codex 验收清单

对每个 Mimo 产出，逐项检查：

1. ☐ 结果满足任务目标
2. ☐ 代码 diff 在授权范围内
3. ☐ 要求的命令已执行并报告结果
4. ☐ UI / 产品 / 数据 / 本地存储行为与当前项目路线兼容
5. ☐ 涉及后端 / 安全 / 测试时，证据齐全（见下方门禁）
6. ☐ 不确定性或残余风险已显式记录

验收通过后：将 inbox 任务移入 `archive/`，记录验收结论。

## 5. Backend Security & Test Gate（后端安全门禁）

当任务触及以下任一：后端代码、API、认证授权、用户数据、文件上传、支付、Webhook、后台任务、第三方集成、管理工具、AI 行为、部署配置——**必须**满足：

**安全最小清单**：
- 认证、会话、Token、密码重置、登出行为
- 授权、角色边界、对象级访问控制、租户隔离（如适用）
- 输入校验、输出编码、注入风险、路径穿越、SSRF、反序列化
- CSRF、CORS、Cookie 标志、速率限制、重放防护（如适用）
- 文件上传校验、内容类型处理、存储权限
- Webhook 签名校验、幂等性、重试、重放窗口
- 密钥处理、环境配置、日志脱敏、错误信息泄露
- 依赖漏洞检查
- 敏感操作的审计日志
- 隐私、留存、删除、导出、合规状态

**测试最小清单**：
- 后端业务规则与权限辅助函数的单元测试
- API / 集成测试：正常路径、校验失败、未授权、跨角色禁止、跨租户访问
- 每个安全修复的回归测试
- 迁移、后台任务、Webhook、队列测试（如涉及）
- UI 与后端耦合的关键流程 E2E 冒烟测试

**验收证据必须包含**：执行的命令、通过/失败结果、按严重度划分的未决发现、显式接受的残余风险、覆盖的文件或流程。

## 6. 角色降级机制

当引入更高级智能体接管策略与委派时：
- Codex 从「主智能体」转为「执行 / 协助角色」
- 由新智能体接管策略制定与任务下发
- 本规范中 Codex 的职责由新智能体继承，Codex 配合实现
- 降级发生时在 `PROJECT.md` 追加记录
