# JobPulse P0 闭环缺口：研究与范围

**日期**：2026-07-28  
**范围**：招聘信息搜集系统产品端  
**明确排除**：营销页、产品设计案例页、CSV/Notion 导入、订阅通知

## 研究依据

本次实现直接承接 [`online-scenario-role-walkthrough-2026-07-28.md`](../research/online-scenario-role-walkthrough-2026-07-28.md) 的两个 P0 发现：

1. 招聘通知中的面试/测评时间没有进入近期安排；
2. 岗位库之外的外部投递无法进入统一时间线。

研究样本来自 19 条公开求职记录与四个边界明确的专家模拟角色。它们是设计输入，不是受访用户数据，也不能被表述为真人可用性测试。

## 用户任务

### 任务 A：从通知到行动

用户粘贴招聘邮件或聊天通知，系统提取公司、岗位、建议状态及明确时间。用户确认后：

- 投递状态完成合法流转；
- 同时创建面试或测评计划事件；
- 详情时间线与近期安排读取同一条计划事件；
- 未确认的解析结果不改状态、不写事件。

### 任务 B：记录岗位库外的投递

用户从任意外部渠道完成投递，即使岗位尚未被系统采集，也能用最少字段建立完整记录：

- 必填：公司、岗位；
- 可选：地点、原始链接、投递日期、备注；
- 一次提交同时生成手动岗位、投递与初始 `applied` 事件；
- 创建成功后进入投递详情，可继续使用现有状态机和时间线。

## 数据与交互原则

1. 计划时间只在邮件中存在明确表达时提取，不推测缺失日期。
2. 邮件解析继续保持只读；写入动作必须由用户确认。
3. 状态事件与计划事件必须同事务提交，任一步失败则全部回滚。
4. 外部投递补录必须原子化，不能先留下无投递的岗位或无初始事件的投递。
5. 手动岗位使用 `source=manual`，原始链接同时作为岗位来源与可访问的投递链接保存。
6. 同一手动岗位已有进行中投递时返回冲突，不静默创建重复记录。

## 验收标准

- 正则降级与 LLM 两条解析路径都能返回 `interview_time`。
- `interviewing + interview_time` 创建 `interview` 待办；`test + interview_time` 创建 `test` 待办。
- 不支持计划事件的状态携带时间时被接口拒绝。
- 计划事件出现在投递详情与 `/todo`。
- 外部投递补录创建岗位、投递、初始事件，并能在投递列表中看到。
- 后端回归测试、前端 lint/build 与桌面浏览器核心路径通过。
