## 1. 执行摘要

本轮调研推翻了旧版“国内没有产品同时提供校招信息库和投递管理”的判断。

截至 2026-08-24：

1. **Offerbiu 类产品是最直接竞品类型**：这类产品同时提供校招信息库和私人求职工作台；Offerbiu 是当前代表性样本，已覆盖投递看板、截止提醒、简历版本、AI 匹配、自动填充和投递复盘，因此不能再把“岗位库 + 投递管理 + 看板”描述为市场空白；
2. **牛客已覆盖招聘批次分类**：公开校招日程包含日常实习、暑期实习、27 届实习、提前批、秋招、春招等维度，“按届别和招聘性质分类”本身不是差异化；
3. **应届生求职网已覆盖截止日期聚合**：其 Deadline 页面提供网申地址、截止日期、进行中/已截止状态和行业筛选，“统一查看 DDL”也不是空白；
4. **实习僧已覆盖实习硬条件**：公开职位展示城市、薪资、每周实习天数和实习周期，“实习条件结构化”只能算基础能力；
5. **国家大学生就业服务平台提供权威公共供给**：国家、省、校三级就业资源与专场招聘是不可忽视的公共替代方案。

JobPulse 更可信的差异化不应是“岗位更多”或“功能更全”，而应是：

> 围绕用户关心的目标公司，持续说明“今天哪些公司开始招聘、增加或关闭了什么、数据来自哪里、覆盖是否完整”，再让用户只把感兴趣的岗位带入私人工作台。

换言之，竞争中心从“岗位库 + Tracker”转向“**可追溯的公司招聘变化雷达 + 私人行动闭环**”。

## 2. 研究方法与证据边界

### 2.1 调研方法

- 调研日期统一记录为 2026-08-24；
- 优先使用竞品官网、公开产品页、服务协议、会员页和政府平台；
- 只把公开页面可观察到的功能写为事实；
- 未登录、未付费或未实际完成的流程标为“未验证”，不根据按钮名称推断完整能力；
- 不使用搜索权重、第三方流量估算或旧媒体报道推算市场份额；
- 历史截图仅用于理解页面结构，不代表 2026-08-24 的实时产品状态。

### 2.2 证据等级

| 等级 | 定义 | 使用方式 |
|---|---|---|
| E1 | 官网当前页面、官方协议、政府公开页面 | 可作为当前功能或政策事实 |
| E2 | 项目在公开演示页完成的页面走查与截图 | 可作为界面事实，需注明日期和登录边界 |
| E3 | 公开求职记录、应用商店描述、第三方报道 | 只用于提出假设，不用于市场份额和需求比例 |
| E4 | 项目推断 | 必须写明“推断/待验证”，不能包装成用户结论 |

本报告不声称已经完成真实用户访谈，也不声称任何竞品拥有或缺少未公开的后台能力。

## 3. 市场与竞争边界

### 3.1 本次研究的具体市场

本次不是分析整个在线招聘市场，而是分析以下任务链：

```text
发现某家公司开始校招
→ 判断招聘批次、届别和实习类型
→ 查看该公司当前招聘入口或岗位变化
→ 跳转官方渠道核验和投递
→ 保存感兴趣岗位
→ 管理自己的投递、截止和下一步行动
```

### 3.2 竞品分层

| 层级 | 产品/替代方案 | 与 JobPulse 的关系 |
|---|---|---|
| 直接竞品类型 | Offerbiu 类“校招信息库 + 求职工作台”产品 | 同时覆盖公共校招信息、私人投递管理，并可能延伸简历和 AI；Offerbiu 是当前代表性样本 |
| 校招信息平台 | 牛客校招、应届生求职网 | 提供公司/职位发现、招聘批次、截止日期和官方投递入口 |
| 场景垂直平台 | 实习僧 | 在实习职位供给和实习硬条件方面直接竞争 |
| 公共服务替代 | 国家大学生就业服务平台 | 提供权威职位、专场招聘和国家/省/校资源 |
| 综合招聘平台 | BOSS 直聘、猎聘、智联、前程无忧 | 职位规模、匹配和沟通能力强，但不是 JobPulse 可无授权采集的数据源 |
| 原始事实源 | 企业招聘官网、官方公众号、官方招聘小程序 | 用户最终核验和投递的权威入口，也是 JobPulse 的优先来源 |
| 工作流替代 | Excel、Notion、飞书表格、备忘录、邮箱、日历 | 灵活且迁移成本低，是私人工作台最强替代品 |

海投网保留在监控名单，但本轮未能稳定访问其官方产品页，因此不把第三方目录中的功能描述写成当前产品事实。

## 4. 五个主要竞争对象

### 4.1 Offerbiu：直接竞品类型的当前代表性样本

**公开定位**：面向大学生和应届生，将校招信息、投递记录、简历、AI 分析和行动计划放进同一工作台。

**当前可观察能力**：

- 秋招总览、投递趋势、临近截止、今日待办和投递台历；
- 校招信息库、常见公司库、手动添加岗位；
- 投递看板、简历管理、简历制作、AI 匹配、简历优化；
- 网申自动填充、投递复盘、个人中心和会员体系；
- 官方协议明确说明信息可能来自公开招聘信息、企业官方页面、用户提交和第三方链接，并提醒最终以企业官方发布为准。

**商业模式**：基础投递管理免费；当前公开会员页显示 VIP `¥18.80/月`、SVIP 季卡 `¥38.80/季`、半年卡 `¥48.80/半年`，主要付费点是校招信息库、简历制作、AI 次数和自动填充。价格属于 2026-08-24 页面快照，未来可能变化。

**优势**：

- 已经覆盖“信息库 → 加入投递 → 管理简历 → AI 优化 → 投递复盘”的长链路；
- 公开演示页降低理解成本，成熟度高于单纯原型；
- 用会员额度控制 AI 成本，商业化路径比 JobPulse 更清楚。

**可争取空间**：

- 产品协议承认校招信息无法保证实时、完整或无误，最终仍需用户回到官方来源核验；
- 公开页面的核心表达是“管理投递和提升网申效率”，不是“解释公司招聘变化和来源覆盖”；
- JobPulse 不应复制其简历制作与 AI 功能矩阵，而应优先证明数据来源、变化事件和覆盖状态。

**威胁等级**：高。Offerbiu 不等于这一竞品类型的全部，后续发现同样连接“校招信息库 + 私人求职工作台”的产品时，应继续纳入直接竞品组。若 JobPulse 继续定位为“校招岗位库 + 投递管理”，与这一类产品的差异不足。

证据：[Offerbiu 工作台](https://offerbiu.com/home/)、[会员页](https://offerbiu.com/pricing/)、[用户服务协议](https://www.offerbiu.com/legal/terms/)、[项目既有内页走查](competitor-offerbiu-innerpages.md)。

### 4.2 牛客校招：校招日程与求职内容生态

**公开定位**：求职首页同时提供校招日程、校招职位、实习职位、社招职位、宣讲、内推、题库、面经和笔试日历。

**当前可观察能力**：

- 招聘批次包括日常实习、暑期实习、春招、届别实习、提前批、秋招和校招；
- 支持城市、行业、企业性质、招聘批次和公司名筛选；
- 列表显示收录日期、地点、网申是否结束和“官网投递/立即投递”；
- 当前公开页面标示企业数量 `24084`，该数字是牛客页面自报，不等于独立审计后的完整公司覆盖率；
- 题库、面经、模拟笔试、内推和企业招聘服务形成供需双边生态。

**商业模式**：求职内容与职位发现面向个人，企业侧通过笔试、AI 面试、雇主品牌、招聘专场等服务商业化；具体价格未在本轮公开页面核验。

**优势**：

- 校招品牌和内容生态强，岗位发现之后可继续刷题、看面经和找内推；
- 招聘批次分类已经覆盖 JobPulse 计划中的多个核心维度；
- 企业端招聘解决方案形成供给侧关系。

**可争取空间**：

- 当前公开页以“公司/招聘批次列表”为中心，没有观察到面向个人解释“与昨天相比新增/关闭多少岗位”的公司变化时间线；
- 页面能展示收录日期和网申状态，但没有观察到来源完整性、最后成功采集和失败降级说明；
- JobPulse 可以服务“我只关心一组目标公司今天发生了什么”，而不是与牛客竞争题库、面经和全量内容社区。

**威胁等级**：高。招聘批次、公司发现和官方跳转不能再作为 JobPulse 的独家卖点。

证据：[牛客校招日程](https://www.nowcoder.com/jobs/school/schedule?tab=1)、[牛客企业服务](https://hr.nowcoder.com/school/recruitment)。

### 4.3 应届生求职网：校招入口与 Deadline 聚合

**公开定位**：提供职位、实习、宣讲会、空中宣讲、Deadline、分类求职和行业招聘入口。

**当前可观察能力**：

- 首页按城市搜索职位和公司，展示主推/星推企业和 2027 届校园招聘入口；
- Deadline 页面按行业和日期浏览网申地址与截止日期；
- Deadline 页面区分正在进行和已截止，并公开页面最后刷新时间；
- 与前程无忧的职位、企业招聘和空中宣讲体系存在产品连接。

**商业模式**：个人侧提供求职信息，企业侧提供招聘发布和推广入口；具体个人会员或企业价格未在本轮公开页面核验。

**优势**：

- Deadline 是明确、成熟且容易理解的校招任务入口；
- 行业、城市、宣讲和网申信息范围广；
- 页面直接给出刷新时间，具备基础时效表达。

**可争取空间**：

- Deadline 聚合解决“什么时候截止”，但没有观察到公司招聘活动的连续变化历史；
- 用户仍需要自己判断某家公司相较昨日增加、关闭或重开了哪些机会；
- JobPulse 应把“截止聚合”视为基础信息，而把公司级快照差分与可解释数据质量作为核心。

**威胁等级**：中高。若 JobPulse 只展示公司列表和截止日期，会退化为更小的应届生求职网。

证据：[应届生求职网](https://www.yingjiesheng.com/)、[Deadline 页面](https://www.yingjiesheng.com/deadline/)。

### 4.4 实习僧：实习场景和硬条件筛选

**公开定位**：面向大学生的实习和校招垂直招聘平台。

**当前可观察能力**：

- 首页区分实习、校招和公司；
- 覆盖产品、运营、技术、设计、金融、制造等职位类别；
- 实习职位公开展示薪资、城市、每周实习天数、实习周期和福利标签；
- 同时提供找实习、找校招、空中宣讲、题库和企业入口。

**商业模式**：个人侧职位发现，企业侧招聘服务；具体价格未在本轮公开页面核验。

**优势**：

- 实习场景心智清晰；
- “几天/周、几个月、薪资”属于求职决策的直接硬条件；
- 职位详情比只按届别分类更贴近实习生实际安排。

**可争取空间**：

- JobPulse 不应与实习僧竞争全行业实习职位量；
- 可以在目标公司雷达中提供“27/28 届、暑期/日常实习、来源更新时间和公司变化”组合；
- 对无法自动确认的实习硬条件，应展示未知值和证据，而不是为了筛选完整而猜测。

**威胁等级**：中。它会分流“我现在就要找一份实习”的用户，但不完全替代目标公司变化监控。

证据：[实习僧官网](https://www.shixiseng.com/)。

### 4.5 国家大学生就业服务平台：权威公共替代方案

**公开定位**：由教育部学生服务与素质发展中心运营，连接国家、省级和校级就业资源。

**当前可观察能力**：

- 提供职位信息、专场招聘、联合招聘、实习岗位、重点领域和就业指导；
- 支持切换省级和校级就业网站；
- 教育部 2026 年促就业政策继续强调公共就业平台、高校平台和相关招聘平台互联互通。

**商业模式**：公共就业服务，不以个人会员付费为目标。

**优势**：

- 权威性和公共服务信任强；
- 国家、省、校资源联动，覆盖 JobPulse 不适合单独承担的公共招聘服务；
- 可承接国企、机关事业单位、重点领域和专场招聘。

**可争取空间**：

- 公共平台主要解决权威岗位供给与就业服务，不以“用户自选目标公司每日变化”作为核心交互；
- JobPulse 可以作为个人层的监控与行动工具，不与国家平台竞争公共基础设施；
- 后续应优先考虑官方跳转或合法数据合作，而不是复制公共平台全部职位。

**威胁等级**：中。它降低了“建立一个更全的校招库”的必要性，也强化了 JobPulse 必须聚焦个人监控任务的结论。

证据：[国家大学生就业服务平台](https://www.ncss.cn/)、[教育部 2026 年国聘行动](https://www.moe.gov.cn/jyb_xwfb/gzdt_gzdt/s5987/202606/t20260602_1438533.html)。

## 6. 差异化机会

### 6.1 应坚持的差异化

#### D1：从岗位瀑布流转为公司招聘变化流

首页回答“整个公司池今天发生了什么”，不是继续堆岗位卡片。核心事件包括：

- 新收录公司；
- 公司开始招聘；
- 公司招聘页面发生更新；
- 可确认的新增岗位、关闭岗位和重开岗位；
- 数据源过期、不完整或失败。

#### D2：把数据可信度做成用户可见能力

每个数字应能下钻到：

- 公司；
- 招聘活动；
- 官方来源；
- 当前与上一有效快照；
- 最后成功更新时间；
- 覆盖范围和失败原因。

这比“24h 更新”口号更容易形成可信差异。

#### D3：公司中心而非公共完整 JD 仓库

公共库保存公司、招聘活动、轻量岗位引用和变化证据；用户跳到官网浏览并投递。只有用户主动收藏时，完整 JD、备注和投递进度才进入私人工作台。

#### D4：公开发现与私人行动连续

竞品常在“信息库”和“投递管理”之间建立加入按钮。JobPulse 需要进一步说明：

- 公共事实与私人数据不会混淆；
- 重复收藏可识别；
- 原岗位关闭后仍保留用户私人证据；
- 插件不能解析时仍允许保存官方链接。

#### D5：合规和失败降级不是后台细节

受限来源不绕过登录、验证码、客户端签名或访问控制。无法完整采集时展示页面更新或来源异常，不把不确定变化计入新增岗位。

### 6.2 不应继续声称的差异化

- “国内没有校招岗位库 + 投递管理产品”；
- “27/28 届、暑期/日常实习分类是独有能力”；
- “统一 Deadline 是市场空白”；
- “实习天数和周期筛选是独有能力”；
- “AI 简历匹配或自动填充能天然形成护城河”；
- “岗位数量越多，产品价值越高”；
- “可以完整收录全网所有岗位”。

## 7. 推荐竞争定位

### 7.1 一句话定位

> JobPulse 是面向国内校招求职者的公司招聘变化雷达：持续监控目标公司官方招聘渠道，解释每天新增、关闭和更新的招聘机会，并把用户真正关心的岗位衔接到私人求职工作台。

### 7.2 优先服务的任务

1. 我有一组想关注的公司，但不想每天逐个刷新官网；
2. 我想知道今天哪些公司开始招聘，以及属于 27/28 届、暑期或日常实习的哪类机会；
3. 我需要确认数据是不是来自官网、什么时候更新、是否可能漏采；
4. 我只想保存真正感兴趣的岗位，而不是维护一个公共完整岗位仓库；
5. 收藏后，我希望继续管理投递、截止和下一步行动。

### 7.3 需要避开的战场

- 与牛客竞争题库、面经、社区和内推；
- 与实习僧竞争全行业实习职位量；
- 与 BOSS/猎聘竞争即时沟通和推荐匹配；
- 与 Offerbiu竞争完整简历制作、AI 优化和自动填充功能数量；
- 与国家就业平台竞争公共岗位基础设施；
- 以无授权抓取换取表面覆盖量。

## 8. 竞争风险与监控项

| 风险 | 观察信号 | 应对 |
|---|---|---|
| Offerbiu 增加公司变化雷达 | 上线公司订阅、岗位差分、来源健康 | 加快可追溯差分闭环，不跟随扩简历功能 |
| 牛客强化公司关注和通知 | 支持公司维度变化订阅、关闭/重开历史 | 聚焦来源证据、覆盖完整性和私人衔接 |
| 官方平台开放数据合作 | 出现标准 API、开放平台或高校互联接口 | 优先合作接入，减少页面采集 |
| 招聘官网加强访问限制 | 公开接口关闭、条款更新、签名增强 | fail-closed、人工公告队列、书面授权 |
| 用户不关心“变化”只关心岗位 | 动态页理解低、仍回到搜索列表 | 在真人访谈和可用性测试中设置停止条件 |

## 9. 对后续文档的影响

- A2 需要把“目标公司机会监控者”提升为核心行为画像候选；
- JTBD 必须增加来源可信度、数据新鲜度、公司变化和失败降级；
- V3 PRD 不再用“高信息覆盖 + 深投递管理”的二维图证明空白；
- 首页指标必须来自快照差分事件，不能用当前岗位总数代替“今日新增”；
- Figma 需要设计首次基线、无变化、过期、不完整和来源失败状态；
- 商业化不能照搬 Offerbiu 的 AI 会员模式，需先验证公司监控是否形成持续使用。
