# JobPulse 三人探索性用户访谈执行包

| 文档项 | 当前定义 |
|---|---|
| 版本 | V2.0（A2 补充研究包评审稿） |
| 日期 | 2026-08-25 |
| 计划样本 | 首轮 3 人，分别覆盖 S1、S2、S3；不是已完成样本 |
| 单次时长 | 25—30 分钟；可选概念任务另加 5 分钟 |
| 研究方法 | 半结构化行为访谈；收集近期真实故事，不推销产品 |
| 执行状态 | 尚未招募，真人访谈完成数为 0 |
| 总方案 | [用户验证执行方案 V2.0](user-validation-plan.md) |

> 三人首轮用于发现行为差异、反例和下一轮问题，不代表主题饱和，不用于计算市场比例。只有当面、语音或视频实时交流并进行追问，才计为访谈；自行填写材料应单独记为开放式问卷。

---

## 1. 这轮访谈要回答什么

本轮希望获得可用于以下决策的真实故事：

1. S1 最近如何监控具体公司的校招或实习机会，手动方式在哪些情况下已经足够；
2. 用户如何判断届别、招聘类型、官方来源、更新时间和岗位是否仍有效；
3. S1 在什么时刻会从“查看信息”进入“收藏、保存或投递”；
4. S2 最近如何把招聘通知关联到岗位、状态和下一步，维护成本发生在哪里；
5. S3 为什么不维护完整台账，邮箱和日历在哪些情况下更好；
6. 哪些行为支持继续整合公共雷达与私人工作台，哪些行为要求收缩或拆分。

本轮不询问“你喜欢 JobPulse 吗”“你会不会用”“你想要什么功能”。

## 2. 样本设计

### 2.1 共通准入条件

- 当前处于中国大陆校招、实习或应届招聘场景；
- 最近发生过可按顺序讲述的岗位发现、公司核验、保存、投递或招聘通知处理行为；
- 愿意讨论实际过程；展示脱敏书签、记录、邮件或日历优先但不强制；
- 现有方式已经足够好的人同样可以参加。

不要求每个人必须使用多个渠道、投递10个以上岗位或拥有完整台账。

### 2.2 三人组合

| 编号 | 主要分群 | 必须核验的近期行为 | 重点反例 |
|---|---|---|---|
| P01 | S1 目标公司机会监控者 | 重复查看过具体公司的官网、公告、公众号或校招清单 | 关注公司很少，书签或公众号已经足够 |
| P02 | S2 活跃投递管理者 | 使用某种方式管理多个处于不同阶段的机会 | 表格更快、更自由，不需要独立工作台 |
| P03 | S3 低维护求职者 | 主要依赖邮件/日历，只在关键节点处理或记录 | 完整台账本身就是额外工作 |

若同一参与者兼具 S1 和 S2，记录主要分群和兼具分群。找不到完全匹配样本时可以访谈，但必须标记偏离条件，不能事后更改分群凑齐组合。

## 3. 招募文案

> 你好，我正在研究校招和实习期间，大家怎样关注目标公司的招聘变化、核对官方信息，以及怎样保存和推进真正感兴趣的机会。想请你回忆最近一次真实过程，交流大约 25—30 分钟，不推销产品，也没有标准答案。你觉得书签、表格、邮箱或日历已经足够好，同样是非常有价值的结论。内容会匿名记录，不公开姓名、账号、联系方式或敏感公司信息。如果方便，可以语音、视频或当面交流。

不要在招募文案中出现“公司变化雷达”“智能聚合”“一站式管理”或具体功能列表，避免参与者提前迎合方案。

## 4. 访谈前筛选

筛选只用于确认近期行为和分群候选，不用于公开展示参与者信息。

1. 当前求职场景：提前批 / 秋招 / 春招 / 补录 / 暑期实习 / 日常实习 / 届别实习 / 其他；
2. 最近一次主动查找公司招聘或处理招聘通知的日期；
3. 最近关注过哪些具体公司；
4. 是否重复查看过某个公司招聘入口：是 / 否；若是，最近一次是什么时候；
5. 最近是否同时有多个收藏、待投递或已投递机会：是 / 否；
6. 使用过哪些方式：官网书签 / 公众号 / 静态清单 / Excel / Notion / 飞书 / 备忘录 / 邮箱 / 日历 / 没有记录 / 其他；
7. 是否愿意在访谈中展示已脱敏的实际工具：是 / 否；
8. 是否参与过 JobPulse 的设计或已经看过完整方案：是 / 否。

### 4.1 初步分群规则

- 重复查看具体公司招聘入口，优先标为 S1 候选；
- 管理多个不同阶段机会，优先标为 S2 候选；
- 很少记录且主要依赖关键通知，优先标为 S3 候选；
- 没有近期真实行为，只表达未来意向，不纳入首轮。

## 5. 主持人开场（2—3 分钟）

> 谢谢你参与。今天想了解你最近真实发生过的求职过程，不是测试你，也不是请你评价一个产品。没有正确答案；如果你现在的方式已经很好，或者根本不需要额外工具，这对研究同样重要。
>
> 我会使用 P01、P02 这样的编号做匿名笔记，不公开姓名、账号、联系方式或敏感公司信息。你可以跳过任何问题，也可以随时结束。屏幕共享和录音都不是必须的，我会分别询问你的同意。请问你是否同意开始？

主持人记录：

- 是否同意参与和匿名记录：是 / 否；
- 是否同意录音：是 / 否 / 未申请；
- 是否同意屏幕共享：是 / 否 / 未申请；
- 是否同意保存脱敏截图：是 / 否 / 未申请；
- 访谈形式：当面 / 语音 / 视频；
- 实际开始时间。

未同意匿名记录则停止访谈；不同意录音、共享或截图不影响继续参与。

## 6. 通用故事主线（8—10 分钟）

### 6.1 最近一次完整过程

1. 请从最近一次你主动查找公司招聘、保存岗位或处理招聘通知的那一刻开始讲，当时发生了什么？
2. 是什么事情让你在那个时间开始行动？
3. 接下来你按什么顺序打开了哪些入口或工具？
4. 你当时需要做出什么决定？最后怎么决定的？
5. 后来发生了什么？这件事什么时候算处理完？

通用追问：

- “最近一次具体是哪一天或哪个招聘阶段？”
- “当时实际点了什么、搜索了什么、记录了什么？”
- “能按时间顺序再走一遍吗？”
- “这个步骤花了多少次打开、切换或回查？”
- “如果方便，可以展示脱敏后的实际记录或入口吗？”
- “这件事带来的是真实机会损失、时间成本，还是只是感觉麻烦？”

不要在故事讲完前切换到产品概念或功能列表。

## 7. S1 分支：目标公司机会监控（6—8 分钟）

对 P01 必问；对其他参与者存在相关行为时追问。

1. 最近一次你连续几天或多次查看同一家公司的招聘信息是什么时候？为什么需要再次查看？
2. 当时具体关注哪些公司？这份公司范围是怎样形成和变化的？
3. 你如何知道某公司“开始招聘了”或者“相较上次有变化”？
4. 最近一次遇到届别、秋招/春招、暑期/日常实习混在一起时，你怎样判断与自己有关？
5. 最近一次看到一条岗位或公告但不确定是否仍有效时，你做了什么？
6. 你怎样判断一个信息来自企业官方、二手转载还是已经过期？
7. 最近一次错过公司活动、截止日期或新岗位是什么时候？实际后果是什么？如果从未错过，现有方式为什么有效？
8. 哪些公司或时期你不会反复查看？为什么？

重点记录：

- 目标公司范围是否具体；
- 重复查看的真实频率与触发；
- 当前书签、公众号、群聊、清单或平台的优势；
- 用于判断的真实字段；
- 没有工具也未造成问题的反例；
- 从查看到收藏或投递的真实转换时刻。

## 8. S2 分支：私人投递与下一步（6—8 分钟）

对 P02 必问；对其他参与者存在相关行为时追问。

1. 最近一次同时有多个机会处于不同阶段是什么时候？你怎样区分它们？
2. 最近一次更新表格、Notion、飞书、备忘录、邮箱分类或日历时，具体更新了什么？
3. 最近一次收到测评、笔试、面试或材料通知时，你怎样确认它对应哪个公司和岗位？
4. 通知中的时间和下一步最终进入哪里？是否还需要在别处重复记录？
5. 最近一次没有及时更新、找不到上下文或停止维护是什么时候？前一刻发生了什么？
6. 这次中断造成了机会损失、时间损失还是没有明显影响？后来怎样补救？
7. 最近一次主动寻找或尝试新工具是什么时候？是什么推动你开始，又是什么让你留下或放弃？
8. 现有方式最不愿放弃的部分是什么？

重点记录：

- 通知到岗位、状态和时间的实际搬运步骤；
- 表格、邮箱和日历已经解决得很好的部分；
- 推动更换的真实事件，而不是口头“愿意”；
- 对权限、自动识别、数据丢失和迁移的焦虑；
- 维护中断是否真的造成损失。

## 9. S3 分支：低维护与非用户反例（5—6 分钟）

对 P03 必问。

1. 最近一次收到需要行动的招聘通知时，你为什么只使用邮箱、日历或记忆就足够？
2. 哪些信息你一定会保存，哪些信息你从来不记录？
3. 最近一次完全不记录也没有出问题是什么时候？为什么现有方式可靠？
4. 有没有一次邮箱、日历或记忆失效？如果没有，不要假设一定存在问题。
5. 你是否尝试过完整台账或专用工具？当时为什么开始，为什么停止？
6. 哪些额外操作、权限或字段会让你立即放弃？

S3 的研究目标不是寻找办法把参与者转化，而是确认产品是否应该停止服务这一场景，或只保留最小关键行动。

## 10. Four Forces 迁移追问

在参与者讲到更换或坚持某种工具时，用以下四类问题继续追问：

| 力量 | 追问 | 记录重点 |
|---|---|---|
| 推力 Push | “原来发生了什么，让你开始寻找别的办法？” | 真实事件、损失和情绪 |
| 拉力 Pull | “新办法当时吸引你的具体是什么？” | 已尝试能力，而非功能愿望 |
| 焦虑 Anxiety | “切换时最担心什么？有没有因此没有继续？” | 权限、数据、学习和可靠性 |
| 习惯 Habit | “现有方式有什么部分让你不愿离开？” | 熟悉、自由、导出和工作流嵌入 |

如果参与者从未尝试更换，直接记录“没有切换行为”，不要用假设问题补齐。

## 11. 结束问题（2—3 分钟）

1. 今天谈到的这些事情里，哪一件最近最影响你的行动？为什么？
2. 有没有我没有问到、但对理解你的实际做法很重要的事情？
3. 你认识最近也发生过类似行为、但做法完全不同的人吗？

感谢参与者，并说明是否会有后续概念测试邀请。不承诺产品一定上线某项功能。

## 12. 可选概念任务（行为访谈结束后，最多 5 分钟）

必须明确告诉参与者：“前面的行为访谈已经结束，下面单独测试一个尚未上线的概念。”概念反馈不得与过去行为证据混为一类。

只展示一条完整路径：

```text
公司变化 → 覆盖/来源 → 官方入口 → 保存或不保存
```

让参与者完成任务，不先解释产品：

1. “假设这是你关注的公司，请找出今天最值得查看的一项变化。”
2. “你是否愿意基于这里的信息采取行动？请边操作边说明判断。”
3. “请找到最终核验岗位的地方。”
4. “如果官网有一个感兴趣但暂时不投的岗位，请处理它；你也可以选择不保存。”

任务后再问：

- “请用自己的话解释你刚才看到的变化和数据状态。”
- “哪一步让你无法判断？”
- “哪一步增加了工作？”
- “什么情况下你仍会用原来的方式？”

“看起来不错”“功能很多”“以后可能会用”只记为态度，不作为需求证据。

## 13. 主持技巧与禁用问法

主持人目标是说话不超过约 20%，跟随有证据的故事，不机械逐题问完。

| 不要这样问 | 改成这样问 |
|---|---|
| “你是不是经常错过岗位？” | “最近一次错过或差点错过是什么时候？如果没有，也请说明。” |
| “公司变化流会不会更方便？” | “最近一次确认公司是否有新机会时，你实际怎么做？” |
| “你愿意安装插件吗？” | “最近一次安装类似工具是什么时候？什么让你安装或放弃？” |
| “你想要哪些功能？” | “当时哪一步最难？你尝试过什么？” |
| “如果有自动提醒你会用吗？” | “最近一次提醒是怎样产生并被处理的？” |
| “这个设计你喜欢吗？” | “请完成这个任务，并指出无法判断的地方。” |

常用追问：

- “请给一个最近发生的具体例子。”
- “然后发生了什么？”
- “你当时为什么选择这个办法？”
- “能展示一下实际做法吗？”
- “这件事让你有什么感受？”
- “如果没有明显影响，为什么？”

## 14. 单人记录模板

每完成一人，在 [访谈结果模板](user-interview-results-3-participants.md) 中建立记录，至少包含：

```text
参与者编号：
主要分群 / 兼具分群：
日期、形式、时长：
同意范围：匿名笔记 / 录音 / 共享 / 截图

最近完整故事：
- 触发
- 实际步骤
- 使用工具
- 决策
- 结果和后果

可观察证据：
- 是否展示实际工具
- 展示了什么（只写脱敏摘要）
- 可核对的时间、入口或行为

Four Forces：
- 推力
- 拉力
- 焦虑
- 习惯

研究分层：
- 观察事实
- 参与者解释
- 研究者推断
- 反例或被推翻假设
- 下一步验证
```

直接引语必须与录音或当场笔记一致。研究者概括不得加引号冒充用户原话。

## 15. 单次访谈质量门禁

满足以下条件才进入主题综合：

- 有至少一个最近真实事件，而不是只有未来观点；
- 能复原触发、步骤、工具、决定和结果；
- 记录至少一个现有方案优势或对 JobPulse 不利的反例；
- 观察事实与研究者推断分开；
- 参与者分群依据明确；
- 同意范围记录完整。

未达到门禁的交流仍可作为背景笔记，但不能为了凑够 3 人计入正式访谈样本。

## 16. 对外表达边界

完成实时访谈后可写：

> 完成 X 名校招/实习求职者的探索性访谈，覆盖目标公司监控、活跃投递管理和低维护反例。

不能写：

- “访谈证明所有用户都需要公司雷达”；
- “3 人中 2 人需要，所以 67% 用户需要”；
- “用户会长期使用或愿意付费”；
- 把概念任务反馈写成过去行为；
- 把开放式问卷、AI 合成角色或专家走查计入访谈人数。
