# 投递管理设计简报（shape-applications）

> TASK-015 产出。投递管理是本产品的差异化命脉，包含 9 状态机可视化、事件时间线、AI 解析、DDL 提醒、纠错机制。
>
> ---
> **版本**：v2（主智能体校准版）
> **v2 修订说明**：v1 整体出色（状态机可视化/快捷流转合法性/纠错 Dialog/AI 三级降级 UI/隐私提示/待办分组都到位），但发现 5 处问题：
> 1. **【中】时间线混入未来事件，语义混乱**：v1 把"未来面试"插在历史事件之间，用户分不清已发生/将发生。v2 改为"即将到来"+"历史"两部分分区
> 2. **【说明】无回应关闭不在快捷菜单**：v1 没说明原因。v2 补充——no_response 由系统建议触发，用户主动放弃用 withdrawn
> 3. **【小】纠错目标状态只列 3 个**：纠错应允许流转到任意状态（含终态）。v2 改为完整 9 状态选择
> 4. **【小】AI 匹配为 null 时无说明**：补充手动选择投递
> 5. **【小】待办缺"标记完成"操作**：补充，否则待办永远不消失

### 1.4 状态流转交互（核心）

**快捷流转**：

点击状态 Badge，弹出快捷菜单（只显示合法的下一状态）：

> ⚠️ **v2 说明：为什么菜单里没有"无回应关闭"？**
> 根据状态机（PRD v3 §3.3），no_response 是**系统建议+用户确认**触发的（>14 天无变更时，系统在待办/看板建议用户标记），不是用户主动选择的流转。
> 如果用户主动想放弃某个投递，应该用"主动撤回"（withdrawn）。
> 这样区分：no_response = "石沉大海，系统帮我发现"；withdrawn = "我主动放弃"。

```
当前状态：已投递
    ↓ 点击 Badge
┌─────────────────────┐
│ → 笔试              │  ← 合法下一状态
│ → 面试中            │  ← 合法下一状态（跳过笔试）
│ → Offer 待决定      │  ← 合法下一状态（直接发 Offer）
│ → 公司拒绝          │  ← 合法下一状态
│ → 主动撤回          │  ← 合法下一状态（用户主动放弃）
│ ─────────────────── │
│ ⚙ 纠错...           │  ← 纠错入口（可流转到任意状态，含终态）
└─────────────────────┘
```

## 二、投递详情 + 事件时间线设计简报

### 2.1 信息架构

| 区块 | 内容 | 说明 |
|------|------|------|
| 头部 | 公司 + 岗位 + 当前状态 Badge + 投递时间 | 核心信息 |

| 操作区 | 状态流转 + 纠错 + 编辑备注 | 快捷操作 |
| 关联岗位 | 链接到岗位详情 | 跳转 |

### 2.2 时间线设计要点

> ⚠️ **v2 关键修正：时间线分"即将到来"+"历史"两部分**
> v1 把未来事件（6-25 面试）插在历史事件之间，用户分不清已发生/将发生。
> v2 改为：时间线**分区**——"即将到来"（未来，occurred_at IS NULL）+ "历史"（已发生，occurred_at IS NOT NULL）。
> 这样用户一眼看清"接下来要做什么"+"之前发生了什么"。

**排序**：
- 即将到来：按计划时间升序（最近的在前）
- 历史：按发生时间倒序（最新在前）

**分区标识**：
- "即将到来"区：带倒计时，高亮背景
- "历史"区：正常背景，按时间倒序

**事件类型展示**：

| 事件类型 | 展示形式 | 说明 |
|---------|---------|------|
| status_change | 状态变更卡片 | from→to + 时间 + 备注 |
| interview | 面试卡片 | 轮次 + 计划时间 + 状态 |
| test | 笔试卡片 | 计划时间 + 状态 |
| material_submit | 材料提交卡片 | 计划时间 + 状态 |
| offer | Offer 卡片 | 时间 + 备注 |
| note | 备注卡片 | 时间 + 内容 |
| correction | 纠错卡片 | 灰色 + "纠错"标签 + from→to + 原因 |

**纠错事件区分**：
- 灰色背景（vs 正常事件白色背景）
- "纠错" Badge 标记
- 显示纠错原因

**待办事件展示**：
- 高亮背景（未来事件）
- 倒计时（"还有 3 天"）
- 关联投递链接

## 三、AI 解析设计简报（F-C.5，亮点）

### 3.1 入口设计

| 入口 | 位置 | 说明 |
|------|------|------|
| 投递列表顶部按钮 | 投递列表页 | 主入口 |
| 全局快捷键 | Ctrl+Shift+U | 快速触发 |
| 详情页操作区 | 投递详情页 | 关联投递 |

### 3.2 解析交互流程

```
用户粘贴邮件文本
    ↓
调用 POST /applications/parse-email
    ↓
返回结果（parsed=true/false, confidence, degraded）
    ↓
展示建议卡片：公司/岗位/建议状态/置信度/匹配的投递
    ↓
用户确认 → 调用 transition API
用户修改 → 修改后确认
用户取消 → 不执行
```

### 3.3 三级降级的 UI 体现

> ⚠️ **v2 补充：matched_application_id 为 null 的处理**
> 当 AI 解析出 company/status 但**没匹配到已有投递**（无投递/多个匹配无法确定）时：
> - 不直接显示"匹配投递"，改为下拉框让用户**手动选择投递**
> - 行为接近 L3（手动选择），但 company/status 建议仍由 AI 提供（节省部分操作）
> 这呼应 ai-parser-module.md v2 §5.1 的"匹配数 0/N 返回 null"逻辑。
