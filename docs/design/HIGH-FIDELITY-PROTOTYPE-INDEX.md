## 二、M1 交互主链与评审重点

桌面主链：`M1-P01 今日变化 → M1-P02 公司库 → M1-P03 公司详情`。

私人数据支线：`M1-P01 / P02 / P03 → M1-P04 收藏与投递 → M1-P05 插件收藏确认`。M1-P05 以 Overlay 形式打开，关闭后返回 M1-P04。

本轮重点评审：

1. 首页六项指标是否表达“整个公司库今天发生的变化”，而不是单一公司的变化；
2. 公司库能否替代全量岗位入库，仍让用户快速找到值得关注的公司；
3. 公司详情是否清楚区分官方公告、招聘活动、轻量岗位索引和来源证据；
4. 插件是否让用户理解“只有主动收藏的岗位才进入私人数据库”；
5. 移动端是否能在一屏内完成指标浏览、截止风险判断和公司变化查看。

当前 M1 原型覆盖核心成功态；加载、空数据、采集失败、插件无法识别和重复收藏等状态已写入 PRD，留到研发前的状态页补充与真人测试阶段。

## 三、既有 M0 设计系统与原型范围

- 4 组变量集合、143 个变量，覆盖原始色板、语义色、尺寸和排版；
- 12 个组件集、48 个变体，覆盖按钮、导航、表单、状态、岗位卡片、投递行、时间线和反馈状态；
- 11 张桌面/业务状态页、3 张移动端页面；
- 桌面主链和移动端主链已配置点击跳转；
- Figma 文件内含 `Cover`、`Foundations`、`Components`、`Desktop`、`Mobile`、`Prototype Flow`、`Handoff` 和 `M1 Recruitment Radar` 页面。

`P01 总览 → P02 发现岗位 → P03 岗位详情 → P04 收藏与待投递 → P05 投递进展 → P06 投递详情 → P14 解析确认 → P07 近期安排`

### 移动端

`P10 收藏岗位 → P11 我的收藏 → P12 投递详情`

## 六、使用规则

1. PRD 的业务规则和验收标准是需求事实源。
2. Figma 与 PRD 冲突时，以 PRD 为准，并登记设计待修。
3. 原型中的演示数据、日期、岗位数量和状态数量仅用于设计表达，不是生产数据。
4. Figma 图用于说明目标体验；旧版实装截图用于说明当前实现，两者不可混用。
5. AI 解析只提取候选字段，不自动改变投递状态；中低置信字段必须由用户确认。
6. 数据采集遇到登录、验证码或访问限制时停止自动化并降级为手动导入。
