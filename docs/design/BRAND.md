## 一、定位声明（真实营销型）

### 1.1 一句话定位

> **为高频求职者设计的投递节奏管理工具**——把分散在 5 个平台的招聘信息收进一个面板，用数据看清自己的求职节奏。

### 1.2 营销面语气（v5 转向，已与用户确认）

**真实营销型**，对标 Linear / Notion / Apple 的产品落地页。

| 维度 | 选择 | 说明 |
|------|------|------|
| 语气 | 专业、清晰、自信，像真实在售的 SaaS | 不夸大，但也不再"自证作品集" |
| CTA | 「免费开始」「开始试用」 | 标准 SaaS 转化语言 |
| 定价页 | 真实营销展示（14 天免费试用/无需信用卡） | 不标注"作品集示意" |
| 社会证明 | 占位区（标注"待真实用户验证"）或客观能力陈述 | 不虚构证言，但可用真实能力数据 |

> v5 转向理由：用户在迭代中明确反馈"查看 Live Demo 不是营销页该有的，太怪"。从作品集自证转向真实营销，更符合用户预期和落地页成熟度标准。视觉设计任务见 `TASK-VISUAL-APPLE-GRADE.md`。

## 二、寄存器决策

### 2.1 选择

**brand register**（品牌寄存器）——营销面专用。

### 2.2 与产品面的隔离规则

| 维度 | 营销面（brand） | 产品面（product） |
|------|----------------|------------------|
| 目标 | 传达价值、建立信任、引导探索 | 任务效率、信息密度、状态可读 |
| 装饰 | 允许 hero、大留白、情绪化视觉 | 克制，拒绝花哨 |
| 字号 | 更大（hero 标题 48-64px） | 紧凑（标题 18-24px） |
| 行距 | 更宽（1.6-1.8） | 紧凑（1.4-1.5） |
| 负空间 | 大量留白 | 高信息密度 |
| 动效 | 允许入场动画、滚动揭示 | 仅状态变化反馈 |
| 文案 | 情绪化、价值主张导向 | 功能性、操作导向 |

### 2.3 共享基础（两套寄存器的公共调色板）

颜色与字体家族**共享** DESIGN.md 定义，但营销面有不同的应用比例：
- 营销面：主色占比更高（hero 区块）、中性色用于大面积留白
- 产品面：状态色是主角（9 状态机），主色仅用于关键操作

## 三、营销面品牌关键词

### 3.1 正向关键词

| 关键词 | 在营销面的体现 |
|--------|--------------|
| **清晰** | 一句话说清"这是什么、为谁"，hero 不绕弯 |
| **可信** | 用真实的产品截图/数据可视化，而非抽象插画 |
| **有温度** | 直击求职焦虑（"信息分散""不知道投到哪了"），但不贩卖焦虑 |
| **专业** | 方法论可见（讲"为什么这样设计"），非套模板 |
| **克制** | 即使是营销页，也拒绝渐变文字、玻璃态、无意义动效 |

### 3.2 反向关键词（营销面也不要）

| 关键词 | 说明 |
|--------|------|
| ❌ 夸大 | 不要"革命性""一键搞定""再也不用愁" |
| ❌ 贩卖焦虑 | 不要"再不投就晚了""别人都拿了 5 个 offer" |
| ❌ 虚假证明 | 不要虚构用户证言、假数据 |
| ❌ 模板感 | 不要看起来像套了某个 SaaS landing page 模板 |
| ❌ 渐变文字 | 与产品面一致，hero 标题用实色 |

> 注意：营销面"允许更多装饰"≠"允许 AI 模板味"。反 AI 模板的底线两套寄存器一致。

## 四、营销面页面清单

### 4.2 落地首页结构（v5 真实营销型，已实现见 web/ 代码）

> 注：以下为 v5 定型结构。实际代码在 `web/components/marketing/`，7 屏已实现并通过 build 验证。

```
第0屏 Hero
   - 大标题：Your job search, in rhythm.（"in rhythm" 用 italic）
   - 副标题：中文价值行（5 平台聚合/状态管理/看清节奏）
   - CTA：「免费开始」+ 副链「看产品演示」
   - 视觉：产品工作台预览（React mockup，DashboardPreview 组件）

   - 3 个痛点卡：信息散落 / 状态记不住 / 看不见节奏

第2屏 信息聚合
   - 左文案"一个面板收齐 5 大平台" + 右岗位收件箱界面

第3屏 投递状态机
   - 左文案"从收藏到 Offer，9 个状态全流程" + 右投递管道工作区

   - 漏斗 + 趋势 + KPI，"用数据看清求职节奏"

   - 8 个能力图标墙（跨平台同步/邮件解析/DDL提醒/去重/批量流转/导出/移动端/本地优先）

第6屏 定价 + CTA + Footer
```

## 五、营销面视觉规则（与 DESIGN.md 共享令牌）

### 5.1 允许的营销面装饰（产品面禁用）

| 元素 | 营销面 | 产品面 |
|------|--------|--------|
| Hero 大区块 + 主色背景 | ✅ | ❌ |
| 入场动画 / 滚动揭示 | ✅（克制，opacity+translate） | ❌ |
| 产品截图大图展示 | ✅ | — |
| 大字号 hero 标题（48-64px） | ✅ | ❌ |
| 大量负空间 | ✅ | ❌ |

### 5.2 两面共同的底线（反 AI 模板）

以下在**任何一面**都禁止（继承 DESIGN.md §1.4 + 反模板清单）：
- ❌ 渐变文字（gradient text）
- ❌ 玻璃态（glassmorphism）
- ❌ 无意义卡片网格（3 列等高 feature 卡配 emoji 图标）
- ❌ 抽象矢量插画占据 hero（用真实产品截图替代）
- ❌ "Trusted by" 灰度 logo 墙（用真实数据或明确占位替代）

## 六、文案语调指南

### 6.1 落地页文案示例

**Hero 标题（候选）**：
- 「为高频求职者设计的投递节奏管理工具」（直白型）
- 「把分散在 5 个平台的招聘信息，收进一个面板」（场景型）
- 「投了 30 个岗位，记得住每个的状态吗？」（提问型）

> 待 TASK-016b shape 时与用户确认最终文案。

**Hero 副标题**：
> 告别在 BOSS、拉勾、牛客、实习僧、企业官网之间来回切换。聚合信息、管理投递状态、用数据看清你的求职节奏。

**CTA 文案**（v5 真实营销型）：
- 主：「免费开始」
- 副：「看产品演示」

### 6.2 痛点区文案示例（不贩卖焦虑）

✅ 「投递记录散落在收藏夹、备忘录、聊天记录里，月底复盘时拼不全。」
✅ 「笔试约了下周三，但藏在某个 App 通知里，差点错过。」

❌ 「再不系统管理，你就会错过人生的 offer！」（贩卖焦虑）
❌ 「一键搞定所有求职问题！」（夸大）

### 6.3 页脚（v5 真实营销型）

> 不再使用"作品集声明"。页脚按真实 SaaS 标准组织：logo + 多栏链接（产品/资源/公司）+ 版权年份。

## 七、与产品面的衔接

### 7.1 路由与导航

```
/                → 落地页（brand register）
/pricing         → 定价页（brand register）
/dashboard       → 看板（product register）  ← 落地页 CTA 指向
/jobs            → 岗位列表（product register）
/applications    → 投递管理（product register）
...其他产品面页面
```

**导航规则**：
- 落地页顶部导航（v5 真实营销型）：「产品」「方案」「资源」「定价」+ 登录 + 免费开始（见 web/Navbar.tsx）
- 产品面顶部导航：应用内导航（看板/岗位/投递/订阅），「返回首页」入口在用户菜单
- 两面共享顶部 logo，但导航项不同

### 7.2 视觉过渡

从落地页 CTA 进入产品面时，**不做强转场动效**（避免营销感污染工具感）。直接路由跳转，靠寄存器差异自然区分。
