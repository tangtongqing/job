# JobPulse 产品设计重构简报

> 状态：已确认  
> 版本：v1.0  
> 日期：2026-07-15  
> 适用范围：SaaS 官网、产品 Demo、作品集案例页

## 一、理解基线

- JobPulse 面向近一个月跨 3 个以上渠道、累计投递 20 个以上岗位的高频求职大学生。
- 本轮同时重构真实 SaaS 官网、产品 Demo，并新增独立作品集案例页。
- 首要成功标准是面试时能够完整、稳定、清晰地演示产品闭环；长期自用属于未来计划。
- 产品核心闭环为：发现岗位 → 收藏/待投递 → 创建投递 → 更新状态 → 处理待办 → 查看进展。
- 保留 9 状态机、SQLite 本地优先、FastAPI + Next.js、合规采集、AI 结果由用户确认、亮暗主题等既有决策。
- 官网保持真实产品语气；作品集页面单独解释研究、取舍、实现与验证，不把幕后叙事混入官网。
- 不伪造访谈结论、客户 Logo、用户评价、增长数字或尚未开放的付费能力。

## 二、目标与非目标

### 2.1 本轮目标

1. 建立官网、产品 Demo、作品集三表面的清晰定位和自然跳转关系。
2. 补齐从岗位发现到进展复盘的产品任务闭环。
3. 用真实产品界面、操作视频和可验证事实替代通用 SaaS 模板表达。
4. 建立稳定的种子数据和可重置 Demo，降低面试现场演示风险。
5. 完成桌面与移动端、亮暗主题、键盘操作和减少动态效果的质量验证。

### 2.2 明确非目标

- 不实现生产级多用户、鉴权、多租户、支付或高可用。
- 不实现邮件、WebSocket 或原生 App 推送。
- 不扩展简历生成、简历匹配或自动投递产品线。
- 不以真实爬虫或第三方 AI Key 作为面试演示的必要依赖。
- 不为视觉效果引入大型动画或 3D 依赖。

## 三、默认约束与非功能要求

| 维度 | 本轮约束 |
|---|---|
| 使用规模 | 单用户、本地 Demo、受控种子数据 |
| 性能 | 首屏媒体优先展示海报帧；非首屏视频延迟加载；移动端使用低分辨率资源 |
| 可靠性 | 核心演示路径可重复运行；支持一键重置 Demo 数据；外部服务不可用不阻断主路径 |
| 安全与隐私 | AI 邮件解析前提示第三方处理风险；解析结果不自动执行状态流转 |
| 可访问性 | 以 WCAG AA 为基线；支持键盘、焦点状态、非纯颜色状态表达和减少动态效果 |
| 响应式 | 桌面面试演示优先，同时保证 390px 移动视口结构可用 |
| 维护 | 单人维护优先；复用现有 React、Tailwind、Framer Motion 和 Lucide 能力 |

## 四、三表面信息架构

```text
SaaS 官网 / ──开始使用──> 产品 Demo /dashboard
     │                         │
     └──查看案例──> /case-study <──了解设计过程──┘
```

### 4.1 SaaS 官网 `/`

- 受众：潜在 JobPulse 用户。
- 任务：理解价值、建立信任、进入产品。
- 主 CTA：开始整理求职进度，进入 Demo。
- 次 CTA：了解产品如何工作。
- 次级入口：查看产品案例。

### 4.2 产品 Demo

主导航顺序：

1. 看板 `/dashboard`
2. 岗位 `/jobs`
3. 收藏与待投递 `/saved`
4. 投递 `/applications`
5. 待办 `/todo`
6. 订阅 `/subscriptions`

`/crawler` 降级为“数据来源/系统工具”，不再占据普通求职者的一级任务流。

### 4.3 作品集案例 `/case-study`

- 受众：招聘方、面试官和产品同行。
- 任务：理解问题、证据、决策、取舍、落地和验证边界。
- 核心出口：体验产品 Demo。

## 五、产品核心任务流

```text
岗位列表
  → 收藏或标记待投递
  → 收藏与待投递页整理优先级
  → 创建投递
  → 快速更新投递状态
  → 生成或查看下一步待办
  → 看板查看有效进展
```

### 5.1 页面职责

| 页面 | 首要问题 | 关键动作 |
|---|---|---|
| 看板 | 我今天应该处理什么？ | 处理临近待办、更新停滞投递、查看新增目标岗位 |
| 岗位 | 哪些岗位值得关注？ | 搜索、筛选、核验、收藏、标记待投递、查看官方来源 |
| 收藏与待投递 | 下一批准备投哪些？ | Tab 分类、移除、批量创建投递 |
| 投递列表 | 每个机会走到哪里了？ | 查询、筛选、批量或快捷更新状态 |
| 投递详情 | 发生过什么，下一步是什么？ | 时间线、备注、待办、AI 邮件解析、确认状态变化 |
| 待办 | 哪些节点临近或逾期？ | 按逾期/今天/未来分组，进入对应投递处理 |
| 订阅 | 我持续关注哪些目标？ | 创建、启停、编辑、删除订阅规则 |
| 系统工具 | 演示数据和来源状态是否正常？ | 查看来源、触发允许的采集、重置 Demo |

## 六、SaaS 官网叙事

官网不采用重复的“图标 + 标题 + 描述”功能卡片网格，改用连续的真实产品工作流。

1. **Hero**：单一价值主张、一个主 CTA、一段真实产品循环视频。
2. **从散落到清晰**：多个招聘来源汇入统一岗位列表。
3. **从收藏到投递**：展示同一岗位的连续状态变化。
4. **每次变化都有记录**：突出 9 状态时间线、历史记录和纠错能力。
5. **今天先做什么**：展示临近待办和低成本状态更新。
6. **看见真实进展**：展示有效进展趋势与漏斗，不鼓励无效海投。
7. **来源与隐私边界**：说明公开来源、低频、robots fail-closed、AI 用户确认。
8. **Beta 与价格**：当前 Beta 免费；Pro、Team 明确标记为规划中。
9. **最终 CTA**：进入预置数据 Demo。

### 6.1 Hero 构图

- 左侧：价值主张、解释文案、主次 CTA。
- 右侧：真实产品界面，展示今日待办、状态时间线与新岗位动态。
- 默认亮色；暗色作为用户可切换体验。
- 产品界面必须是真实可运行界面或真实录屏，不使用代码绘制的假仪表盘。

## 九、视觉系统

### 9.1 色彩

- 主背景：接近纯白的中性底色，不使用奶油/沙色 SaaS 模板。
- 主文字：深炭黑。
- 主强调：现有靛蓝，仅用于 CTA、当前状态、选中和关键连接。
- 状态色：保留语义区分，同时始终搭配文字或图标。
- 暗色：作为完整主题维护，但不作为官网默认。

### 9.2 排版

- 官网：Inter 为主体；Instrument Serif 仅用于少数情绪性强调词。
- 产品：全部使用 Inter，采用紧凑固定字号和清晰数据对齐。
- 案例：Inter 负责正文与数据；Serif 用于少量章节转折和重要结论。

### 9.3 形状与层级

- 卡片、视频与大容器圆角控制在 8–16px。
- 边框与大阴影不叠加使用。
- 品牌视觉母题是贯穿岗位、投递、待办和进展的“状态轨迹”，不额外添加抽象粒子或装饰波纹。

## 十、动画与真实视频

### 10.1 三层动态表达

1. **Hero 循环视频**：12–18 秒，依次完成浏览岗位、待投递、创建投递、更新状态、生成待办和查看看板。
2. **工作流短视频**：发现、投递、跟进、复盘各 5–8 秒；滚动到章节时切换。
3. **界面微动效**：来源汇入、状态节点点亮、待办插入、图表更新、CTA 和主题反馈。

产品 Demo 内部动效控制在 150–220ms；官网章节切换控制在 450–700ms。禁止弹跳、无限漂浮、背景粒子、装饰性 3D 和统一套用的区块淡入。

### 10.2 视频产物

- 官网 Hero 桌面循环视频。
- 四段工作流章节短视频。
- 作品集 60–90 秒完整演示视频，手动播放并提供字幕。
- 桌面与移动海报帧、关键页面截图。

### 10.3 降级

- 视频静音、循环、内联播放。
- 加载失败展示同构海报帧。
- 移动端加载更低分辨率资源。
- `prefers-reduced-motion` 下停用滚动动画和自动播放，使用静态关键帧。
- 内容默认可见，不把正文可见性绑定到动画完成。

## 十一、异常与边界状态

- 后端离线、请求超时、无岗位、无投递、无待办。
- 收藏、待投递、订阅或状态更新失败。
- 重复创建投递、重复收藏和非法状态流转。
- AI 无 Key、限流、解析失败、结果不确定和隐私提示。
- 采集源禁用、robots 不允许或真实采集不可用。
- Demo 数据已被修改，需要快速恢复。
- 视频加载失败、低性能设备和减少动态效果。

每个错误状态必须说明发生了什么、用户还能做什么，并提供重试、返回或继续使用非依赖功能的路径。

## 十二、实施工作包

1. **设计基线**：同步信息架构、视觉系统、决策日志和文档台账。
2. **产品闭环**：补齐 `/saved`、`/subscriptions` 和相关端点；重组导航；重构看板与待办；建立 Demo 数据重置。
3. **营销与案例**：重做 `/`；新增 `/case-study`；使用真实产品叙事。
4. **视频与质量**：自动录制真实操作；接入媒体降级；完成浏览器、响应式、主题和可访问性验证。

## 十三、验收标准

- 后端测试通过，新增端点有契约和自动化覆盖。
- 前端 lint、类型检查与生产构建通过。
- 收藏/待投递/创建投递/状态流转/待办/看板数据形成真实闭环。
- 官网、产品、案例页之间的 CTA 和返回路径全部有效。
- 1366×768 与 390×844 视口完成亮暗主题浏览器验证。
- 关键操作可通过键盘完成，焦点可见，正文与控件满足 WCAG AA 对比度。
- `prefers-reduced-motion` 下功能与内容完整。
- 完成一遍从官网进入 Demo、执行核心任务、打开案例页解释决策的面试演示。
- 真实视频、海报帧和截图文件存在，且内容与当前产品版本一致。

## 十四、决策日志

| 决策 | 备选方案 | 选择理由 |
|---|---|---|
| 同一站点承载官网、Demo、案例页 | 官网案例融合；案例独立站点 | 保持 SaaS 语气纯净，同时降低部署和面试切换成本 |
| 官网 `/`，案例 `/case-study` | 作品集作为首页 | 官网继续面向潜在用户，案例作为独立证据入口 |
| 产品主线优先展示任务闭环 | 继续按模块并列展示 | 面试演示需要清晰因果和可重复路径 |
| `/saved` 合并收藏与待投递 | 两个独立一级页面 | 两者同属投递前整理阶段，合并可降低导航复杂度 |
| 采集管理降为系统工具 | 保持一级导航 | 手动爬虫不是普通求职者的主任务 |
| 当前 Beta 免费，未来套餐标记规划中 | 展示可购买的 Free/Pro/Team | 保持真实 SaaS 语气且不虚构付费能力 |
| 真实产品视频作为官网主视觉 | 代码绘制假仪表盘；抽象品牌动画 | 产品证据比装饰更可信，也能服务面试演示 |
| 消费产品聚焦感 + SaaS 产品证据 | 复制单一品牌风格 | 兼顾清晰、可信和 JobPulse 自身任务语境 |
| 强动画集中在官网和案例页 | 产品面也使用强叙事动画 | 产品面服务效率，动效只应表达状态 |
| 不扩展简历 AI 产品线 | 模仿 Huntr/Teal/Simplify | 保持聚合、状态管理和待办复盘的差异化 |

## 十五、已知风险

- 用户访谈和可用性测试仍未完成，当前核心需求主要来自问题假设、竞品研究和作者场景。
- 真实采集与第三方 AI 受外部环境影响，不能成为面试 Demo 的硬依赖。
- 设计系统文档与当前 CSS Token 存在历史漂移，实施前需要统一。
- 项目当前没有 Git 仓库，重构前缺少可靠的版本基线与回滚能力。
