# 状态机交互参考映射表（供 craft/polish 对照）

> 目的：在我们等用户找设计参考期间，预先整理业界已验证的状态机交互模式。
> 用户参考回来后，本表用于快速对照"哪些复用、哪些要改、哪些超越"。

> **v2 更新**（2026-06-24）：用户提供的 8 张参考图经澄清为**营销面参考**（落地页/定价页），归入 §六「营销面参考映射」。本表前五章（§一~五）仍为产品面参考。

## 一、Linear（头号参考：工具型产品的状态机标杆）

### 1.1 可复用的交互模式

| Linear 模式 | 我们的对应 | 复用度 | 说明 |
|------------|-----------|--------|------|
| Issue 状态点击 → 弹出流转菜单 | 投递状态 Badge 点击 → 快捷流转菜单 | ✅ 直接复用 | Linear 的菜单只显示合法下一状态，正是我们要的 |
| 状态用颜色 + 图标区分 | 9 状态语义色（DESIGN.md v2） | ✅ 直接复用 | Linear 紫色主题，我们要 9 色，但"颜色+图标"模式一样 |
| 键盘快捷键（C 创建、Esc 关闭） | F-C.5 全局快捷键 Ctrl+Shift+U | ✅ 复用思路 | 工具型产品的标配 |
| 时间线垂直展示事件 | 投递事件时间线 | ✅ 直接复用 | Linear 的 activity feed 是范本 |
| 极简留白、信息密度高 | product register 效率优先 | ✅ 直接复用 | 我们的寄存器选择一致 |

### 1.2 需要调整的差异

| Linear | 我们 | 为什么不同 |
|--------|------|-----------|
| 状态少（Backlog/Todo/InProgress/Done/Cancel） | 9 状态 | 求职流程更细 |
| 英文为主 | 中文展示 + 英文 code | 本地化 |
| 团队协作（多人） | 单用户 Demo | 不需要协作功能 |
| 深色为主 | 亮色为主（暗色预留） | 求职者白天用 |

## 三、Greenhouse/Lever（招聘状态机的专业实现）

### 3.1 可复用的交互模式

| ATS 模式 | 我们的对应 | 复用度 | 说明 |
|---------|-----------|--------|------|
| Candidate pipeline 视图 | 投递状态机的可视化 | ✅ 核心 | 这就是招聘状态机的成熟范本 |
| Stage 流转（拖拽或点击） | 状态流转 | 🟡 思路参考 | 我们用点击菜单，不用拖拽（列表场景） |
| Rejection reason 记录 | 纠错原因记录 | ✅ | 结构化记录原因 |
| Pipeline 转化率 | 投递漏斗 | ✅ | ATS 天然有漏斗概念 |

### 3.2 差异

| ATS | 我们 | 为什么 |
|-----|------|--------|
| 招聘方视角（候选人 pipeline） | 求职者视角（我的投递） | 视角相反，但状态机逻辑相通 |
| 企业级复杂功能 | 个人 Demo | 大幅简化 |

## 四、我们的独特设计点（参考系统没有的）

这些是参考系统不具备、需要我们原创的：

| 独特点 | 说明 | 设计挑战 |
|--------|------|---------|
| **9 状态的色彩区分** | Linear 只有 5 状态，我们要 9 个清晰可辨 | 需要更细的色调分组（DESIGN.md v2 已解决） |
| **AI 解析三级降级 UI** | 没有参考系统有这个 | 绿/黄/提示三卡设计，需原创 |
| **纠错不污染时间线** | Linear 可编辑历史，但不区分"纠错" | 灰色 + 标签的区分设计 |
| **无回应关闭（系统建议触发）** | 没有参考 | 系统建议 + 用户确认的交互 |
| **低成本状态更新（粘贴邮件）** | 没有参考 | AI 解析 + 用户确认的流程 |

## 六、营销面参考映射（v2 新增，基于用户提供的 8 张图）

> 用户提供的 8 张参考图经澄清，是为**营销面**（落地页 `/` + 定价页 `/pricing`）准备的，非产品面。

### 6.1 8 张图的分析结论（已与用户对齐）

| 图 | 识别为 | 寄存器归属 | 复用价值 |
|----|--------|-----------|---------|
| 图 8（ClarityUI）| 仪表盘截图 | 产品面（但作为营销面"产品截图"素材）| ✅ 可作为落地页 hero 区的产品展示截图 |
| 图 7（KPI 数字）| 大数字 KPI 展示 | 营销面（hero 数据展示）| ✅ 落地页"产品价值"区的数据可视化样式 |
| 图 1-6（营销/落地页）| 各类 SaaS 落地页 | 营销面 | ✅ hero 布局、feature 区块、CTA 样式参考 |

### 6.2 营销面可复用模式

| 参考模式 | 我们的对应 | 复用度 | 说明 |
|---------|-----------|--------|------|
| Hero 大标题 + 副标题 + 双 CTA | 落地页 hero 区 | ✅ 复用结构 | 文案改为作品集展示型（见 BRAND.md §6） |
| 三列 feature 卡片 | 核心价值三段 | 🟡 调整 | 参考用 emoji 图标，我们改用真实产品截图片段 |
| 大数字 + 标签的 KPI 展示 | 落地页数据展示 | ✅ 复用 | 用真实采集/投递数据，非虚假 |
| 三档定价卡片（中间高亮）| 定价页 Free/Pro/Team | ✅ 复用 | 加"作品集商业化思考展示"声明 |
| 产品截图大图展示 | 落地页产品演示区 | ✅ 复用 | 用我们自己的看板截图 |

### 6.3 营销面必须避免的（反 AI 模板）

| 参考中常见但我们拒绝 | 理由 |
|---------------------|------|
| 渐变文字 hero 标题 | 反 AI 模板底线（两面一致） |
| 玻璃态卡片 | 同上 |
| "Trusted by" 灰度 logo 墙 | 无真实客户，用占位或作者数据替代 |
| 抽象矢量插画占 hero | 用真实产品截图替代 |
| 夸大营销文案 | 作品集定位，诚实为先 |

### 6.4 与产品面的视觉协调

- **共享**：颜色家族、字体家族（DESIGN.md 令牌）
- **差异**：营销面更大字号、更宽行距、更多负空间、允许入场动画（BRAND.md §2.2）
- **过渡**：落地页 CTA → 产品面不做强转场，靠寄存器差异自然区分
