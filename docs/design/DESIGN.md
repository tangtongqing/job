## 一、设计原则

### 1.1 效率优先

> 求职者时间宝贵，操作路径要短。

- 核心操作（投递、状态更新）不超过 2 次点击
- 筛选条件默认收起，高级筛选按需展开
- 批量操作支持（多选投递、批量状态更新）

### 1.2 状态可读

> 9 状态机必须在 UI 上清晰区分。

- 每个状态有独立的颜色+图标+文字标签
- 进行中状态与终态视觉区分明显
- 状态流转有动画反馈（但克制，不花哨）

### 1.3 信息分层

> 仪表盘要一眼看到关键数据，详情要结构化。

- 仪表盘：KPI 卡片 → 漏斗 → 趋势 → 分布，由总到分
- 列表页：关键信息前置，详情按需展开
- 详情页：分区块展示，避免信息堆砌

### 1.4 克制装饰

> 拒绝渐变文字/玻璃态/无意义卡片。

- 装饰服务于信息传达，不为装饰而装饰
- 动画仅用于状态变化反馈，不用于炫技
- 卡片内容决定样式，不套统一模板

### 1.5 状态完整

> 每个组件要有空/加载/错误态。

- 空状态：引导用户下一步操作
- 加载状态：骨架屏或 Spinner
- 错误状态：友好提示 + 重试按钮

## 二、色彩系统

### 2.1 主色（Primary）

| 色值 | 名称 | 用途 |
|------|------|------|
| `#2563EB` | 蓝-600 | 品牌识别、主要 CTA、链接 |
| `#3B82F6` | 蓝-500 | 悬停状态 |
| `#1D4ED8` | 蓝-700 | 按下状态 |
| `#EFF6FF` | 蓝-50 | 浅色背景、选中态 |

### 2.2 状态语义色（核心）

> 呼应 9 状态机，每个状态有独立语义色。
> **v2 修正**：applied 原错误用 #6B7280（与 no_response 同色），违背状态可视化原则。进行中状态统一用冷色调（蓝/青/紫），终态用灰/红/绿，确保 9 状态清晰区分。

| 状态 | 英文 code | 色调 | 色值 | 用途 |
|------|-----------|------|------|------|
| 已投递 | `applied` | 中性蓝 | `#3B82F6`（蓝-500） | 进行中-初始（v2 修正） |
| 测评笔试 | `test` | 中性青 | `#0891B2` | 进行中 |
| 面试中 | `interviewing` | 中性紫 | `#7C3AED` | 进行中-关键 |
| Offer待决定 | `offer_pending` | 琥珀 | `#D97706` | 需用户行动 |
| Offer已接受 | `offer_accepted` | 成功绿 | `#059669` | 终态-成功 |
| Offer已婉拒 | `offer_declined` | 中性灰深 | `#6B7280`（gray-500） | 终态-用户主动（重大决策，v2 加深） |
| 公司拒绝 | `rejected` | 警告红 | `#DC2626` | 终态-失败 |
| 无回应关闭 | `no_response` | 中性灰 | `#9CA3AF`（gray-400） | 终态-超时（v2 调浅，与 applied 区分） |
| 主动撤回 | `withdrawn` | 中性灰浅 | `#D1D5DB`（gray-300） | 终态-用户主动（常规操作，v2 最浅） |

**色调分组（v2 设计逻辑）**：
- **进行中**（4 个）：冷色调（蓝/青/紫/琥珀）—— 视觉活跃，提示"需要关注"
- **终态-积极**（1 个）：绿（offer_accepted）—— 成功
- **终态-失败**（1 个）：红（rejected）—— 失败
- **终态-中性**（3 个）：灰度梯度（declined 深 > no_response 中 > withdrawn 浅）—— 按重要性区分

### 2.3 功能色

| 用途 | 色值 | 说明 |

| 级别 | 色值 | 用途 |
|------|------|------|
| gray-50 | `#F9FAFB` | 页面背景 |
| gray-100 | `#F3F4F6` | 卡片背景、输入框背景 |
| gray-200 | `#E5E7EB` | 边框、分隔线 |
| gray-300 | `#D1D5DB` | 禁用态边框 |
| gray-400 | `#9CA3AF` | 占位文字 |
| gray-500 | `#6B7280` | 次要文字 |
| gray-600 | `#4B5563` | 正文文字 |

### 2.5 主题

- **亮色主题**：默认，为主
- **暗色主题**：列为未来版本

> **v2 补充：CSS 变量化预留暗色主题**
> 所有色彩通过 CSS 变量（Tailwind 的 `--color-*` 或自定义 `:root` 变量）定义，而非硬编码色值。
> 这样未来实现暗色主题时，只需切换变量值，组件无需改动。
> 示例：用 `bg-primary` 而非 `bg-[#2563EB]`，用 `text-status-applied` 而非 `text-[#3B82F6]`。

## 八、反 AI 模板清单

> 明确列出本项目**拒绝**的设计模式。

| 模式 | 说明 | 为什么拒绝 |
|------|------|-----------|
| ❌ 渐变文字 | `background-clip: text` 彩虹渐变 | 花哨、不专业、降低可读性 |
| ❌ 装饰性玻璃态 | `backdrop-filter: blur` 毛玻璃 | 过度装饰、性能开销、product register 不需要 |
| ❌ 重复等大卡片网格 | 所有卡片相同大小、相同结构 | 信息层次不清、视觉疲劳 |
| ❌ 每个区块 all-caps eyebrow | 大写小标题 | 模板感强、中英文混排不友好 |
| ❌ 无意义的 01/02/03 标记 | 装饰性序号 | 无实际意义、占用空间 |
| ❌ 大阴影幽灵卡 | 大阴影 + 透明背景 | 视觉重量不匹配、信息层级混乱 |
| ❌ 只有 happy path 的 UI | 无空状态、无错误状态 | 不真实、面试会被追问 |
| ❌ 自动播放动画 | 页面加载自动播放 GSAP | 干扰用户、product register 不需要 |
| ❌ KPI 数字 count-up 动画 | 看板数字滚动动画（v2 替换，比"全屏 hero"更相关） | 求职看板常见 AI 味、浪费时间、数字应直接显示 |
| ❌ 装饰性进度环/仪表盘 | 无数据意义的环形进度（v2 替换） | 视觉噪音、product register 不需要 |
