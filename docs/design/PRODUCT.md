# PRODUCT.md · 产品/品牌定位上下文

> 阶段 3 设计初始化产出。确立产品定位、寄存器决策、产品性格、核心用户任务。

---

## 一、产品定位

### 1.1 一句话定位

> 面向大学生的招聘信息聚合+投递管理工具，用数据看板掌握求职节奏。

### 1.2 目标用户

| 画像 | 定位 | 说明 |
|------|------|------|
| **P1 林晓** | 核心画像 | 近一个月跨 3 个以上渠道、累计投递 20 个以上岗位的高频求职者 |
| P2 周明 | 次要画像 | 实习定向型，核心需求超出 MVP 能力边界 |
| P3（P1延伸） | P1 生命周期 | 秋招失败后的复盘阶段 |

### 1.3 核心价值

| 价值 | 说明 |
|------|------|
| **信息统一** | 告别在 BOSS/拉勾/牛客/实习僧/企业官网之间来回切换 |
| **投递闭环** | 从「收藏→投递→笔试→面试→Offer/拒绝」全状态管理 |
| **数据驱动** | 用看板看清自己的求职节奏与转化 |

## 二、寄存器决策

### 2.1 选择

**product register**（产品寄存器）

### 2.2 理由

- 本项目是**应用/工具型**产品（仪表盘+列表+表单+工作流），非品牌营销页
- 设计服务于**任务效率**，而非品牌表达
- 用户目标明确：快速查看岗位、管理投递、分析数据

### 2.3 影响

| 影响 | 说明 |
|------|------|
| 效率优先 | 操作路径要短，信息密度要高 |
| 克制装饰 | 拒绝花哨效果，专注功能 |
| 状态可读 | 9 状态机必须在 UI 上清晰区分 |
| 信息分层 | 仪表盘一眼看到关键数据，详情要结构化 |

## 三、产品性格关键词

### 3.1 正向关键词

| 关键词 | 说明 |
|--------|------|
| **高效** | 求职者时间宝贵，操作路径要短 |
| **可信赖** | 数据准确，状态清晰，不误导 |
| **清晰** | 信息分层，主次分明，不混乱 |
| **专业** | 工具感强，非玩具，可展示给面试官 |
| **克制** | 不过分花哨，专注核心价值 |

### 3.2 反向关键词（不要什么）

| 关键词 | 说明 |
|--------|------|
| ❌ 花哨 | 不要渐变文字、玻璃态、无意义动画 |
| ❌ 模糊 | 不要信息堆砌、主次不分 |
| ❌ 信息过载 | 不要一屏塞太多，要有呼吸感 |
| ❌ 模板感 | 不要看起来像套模板，要有设计感 |

## 四、核心用户任务

### 4.1 任务与页面映射

| 核心任务 | 对应页面 | 优先级 | 说明 |
|---------|---------|--------|------|
| 查看岗位列表 | `/jobs` | P0 | 筛选、排序、分页 |
| 查看岗位详情 | `/jobs/[id]` | P0 | JD、投递链接、收藏/投递 |
| 管理投递状态 | `/applications` | P0 | 状态流转、时间线 |
| 查看投递详情 | `/applications/[id]` | P0 | 时间线、待办、备注 |
| 查看看板数据 | `/dashboard` | P0 | KPI、漏斗、趋势、分布 |
| 管理收藏/待投递 | `/saved` | P0 | Tabs 切换收藏/待投递（v2 合并，减少导航复杂度） |
| 查看待办 | `/todo` | P0 | 笔试/面试/材料提交 |
| 管理订阅 | `/subscriptions` | P1 | CRUD 订阅规则 |
| 采集管理 | `/crawler` | P1 | 触发采集、查看日志 |
| AI 解析邮件 | 弹窗/侧边栏 | P1 | 粘贴文本、确认结果 |

### 4.2 页面层级

```
/                         → 首页/看板
/jobs                     → 岗位列表
/jobs/[id]                → 岗位详情
/applications             → 投递列表
/applications/[id]        → 投递详情/时间线
/saved                    → 收藏/待投递（Tabs 切换，v2 合并）
/todo                     → 待办视图
/subscriptions            → 订阅管理
/crawler                  → 采集管理
```
