## 零、执行摘要

| 维度 | 结论 |
|---|---|
| 核心人群 | 近一个月跨 3 个以上渠道、累计投递 20 个以上岗位的高频求职者 |
| 核心任务 | 聚合岗位、区分收藏与待投递、持续记录投递状态、明确近期行动、复盘转化 |
| 现有替代 | 招聘平台 + Excel/Notion/备忘录的人工组合 |
| 主要缺口 | 信息覆盖与投递管理分离；跨平台状态、时间线和个人转化缺少统一工作台 |
| 产品机会 | 用“公开岗位聚合 + 深度投递管理 + 数据看板”连接发现、行动与复盘 |
| M0 策略 | 先做可验证的作品集 Demo；不以早期 TAM/SAM/SOM 估算替代真实使用验证 |
| 升级条件 | 5–8 次真人访谈、3–5 次原型/可用性测试和作者持续真实投递记录出现复用信号 |

MRD 负责说明“为什么做、为谁做、机会是否成立”；具体功能、流程、状态机与验收标准以 [PRD](PRD.md) 为准，项目形态与投入边界以 [项目章程](PROJECT-CHARTER.md) 为准。

## 一、市场背景

### 1.1 大学生求职市场宏观背景

**应届生规模**
- 2025 年全国高校毕业生达 **1222 万人**，较 2024 年增加 43 万，再创历史新高（[教育部官方，2024-11](http://www.moe.gov.cn/jyb_xwfb/s5147/202411/t20241115_1163118.html)）
- 毕业生规模连续 8 年增长，就业总量压力大（[中国政协网，2025-07](http://www.cppcc.gov.cn/zxww/2025/07/08/ARTI1751941152786361.shtml)）
- 互联网/科技行业仍是大学生求职热门方向，但近两年头部企业 HC 收缩，竞争加剧
- ⚠️ 注：教育部未发布权威的应届生整体就业率，市面流传的"55.5%"等数字来源不可溯，本报告不采用；判断求职难度应依赖"毕业生规模持续增长 + 平台投递量"等可验证指标

**求职周期特征**
- 秋招（8-11月）：互联网大厂集中招聘，岗位数量多、竞争激烈
- 春招（2-4月）：补录为主，岗位数量少、时间窗口短
- 实习招聘：全年滚动，但暑期实习（3-6月申请）是主力

**信息获取现状**
- 多平台分散：BOSS直聘、牛客网、拉勾、实习僧、企业官网、学校就业网
- 信息过载：同一岗位多平台重复，信息不一致
- 手工记录：大学生主流用Excel/备忘录记录投递状态，效率低、易遗漏

### 1.2 趋势判断

**AI求职工具兴起**
- AI简历优化、AI模拟面试、AI职位推荐等工具涌现
- 但AI在"投递管理"和"数据看板"领域的应用仍空白

**数据驱动决策普及**
- 产品经理、数据分析师等岗位的求职者更重视"用数据说话"
- 但现有工具缺乏个人求职数据的可视化和分析能力

**垂直化趋势**
- 综合平台（BOSS、拉勾）功能大而全，但不够聚焦
- 垂直工具（超级简历、牛客）在细分场景有优势，但覆盖面有限

## 二、市场规模估算（TAM-SAM-SOM）

### 2.1 估算逻辑

采用**自下而上**估算方法，从目标人群出发，逐层收窄。

### 2.2 TAM（总可服务市场）

**定义**：全国有求职需求的大学生总量

**估算**：
- 2025年高校毕业生：1222万人
- 其中约70%有主动求职需求：1222万 × 70% = 855万人
- 假设ARPU（年均付费意愿）：0元（Demo阶段免费，未来可参考招聘平台会员定价50-100元/年）
- **TAM ≈ 855万人**（如按付费计算，潜在市场约4.3-8.6亿元/年）

### 2.3 SAM（可服务市场）

**定义**：互联网/科技方向求职的大学生（本项目核心目标人群）

**估算**：
- 互联网/科技方向求职者占比约 30%（估算依据：BOSS 直聘历年年报显示互联网为投递量最大行业，约占全平台 25-35%；本项目取中位值）
- 855 万 × 30% = 257 万人
- **SAM ≈ 257 万人**（量级估算，用于判断市场是否足够大，不用于收入预测）

### 2.4 SOM（可获得市场）

**定义**：Demo阶段实际可达规模

**估算**：
- Demo阶段目标：覆盖10-20所重点高校，约5000-10000名活跃用户
- 如产品验证成功，上线后第一年目标：5-10万注册用户，1-2万月活
- **SOM ≈ 5000-10000人（Demo）/ 5-10万人（上线后第一年）**

### 2.5 市场规模结论

| 层级 | 规模 | 说明 |
|------|------|------|
| TAM | 855万人 | 全国有求职需求的大学生 |
| SAM | 257万人 | 互联网/科技方向求职大学生 |
| SOM | 5000-10000人（Demo） | 重点高校种子用户 |

**结论**：市场基数足够大，即使只切入很小的细分市场，也有足够的用户规模支撑产品验证。

## 三、竞争格局

### 3.1 竞争定位图（文字描述）

**坐标轴定义**：
- X轴：**信息覆盖度**（职位信息的数量和来源广度）
- Y轴：**投递管理深度**（状态追踪、数据看板、复盘分析的能力）

**竞品位置**：
```
投递管理深度 ↑
              │
              │                    LinkedIn Jobs
              │                    （全球覆盖，有基础看板）
              │
              │  超级简历
              │  （简历+投递管理，有状态标记）
              │
              │─────────────────────────────────────→ 信息覆盖度
              │
              │  牛客网    实习僧    BOSS直聘    拉勾
              │  （校招）  （实习）  （全行业）  （互联网）
              │
              │  看准网
              │  （公司信息）
              │
              │                              ★ 本项目
              │                              （多源聚合+深度投递管理+数据看板）
```

**关键发现**：
- 现有竞品在"信息覆盖度"维度竞争激烈，但在"投递管理深度"维度普遍薄弱
- 本项目定位在**右上角空白区域**：高信息覆盖度（多源聚合）+ 高投递管理深度（状态机+数据看板）

### 3.2 波特五要素分析（简化版）

| 要素 | 分析 | 对本项目的影响 |
|------|------|---------------|
| **现有竞争者** | BOSS、牛客、实习僧等综合/垂直平台，但投递管理功能弱 | 有机会切入差异化赛道 |
| **替代品** | Excel、Notion、备忘录等手工工具 | 用户习惯已形成，需提供明显更好的体验 |
| **买方议价能力** | 求职者对免费工具敏感，付费意愿低 | Demo阶段免费，降低用户获取门槛 |
| **供应商** | 招聘平台数据源（公开页面、API） | 合规风险需管控，低频采集是关键 |
| **新进入者** | 大平台可能补投递管理功能 | 先发优势+垂直聚焦是护城河 |

### 3.3 竞争格局结论

- 本项目在竞争定位图中占据**空白位置**：多源聚合+深度投递管理
- 现有竞争者在投递管理维度普遍薄弱，短期内不会重点投入
- 替代品（Excel等）是主要竞争对手，需提供明显更好的体验
- 大平台可能补功能，但本项目聚焦大学生垂直场景，有机会建立先发优势

## 四、机会判断

### 4.1 市场空白点分析

基于TASK-001识别的3个市场空白点，逐一判断：

#### 空白点1：投递状态管理缺失

| 维度 | 判断 |
|------|------|
| **空白是否真实** | ✅ 真实。所有竞品（牛客、实习僧、BOSS、拉勾）均仅提供基础投递记录，无完整状态机 |
| **空白是否可持续** | ✅ 可持续。投递管理不是大平台的核心价值（他们靠招聘方付费），不会重点投入 |
| **与本项目能力匹配度** | ✅ 高。技术实现简单（状态机+数据库），产品设计是核心 |
| **结论** | **做** |

#### 空白点2：数据看板缺失

| 维度 | 判断 |
|------|------|
| **空白是否真实** | ✅ 真实。现有竞品均无个人求职数据看板，LinkedIn有基础但不聚焦 |
| **空白是否可持续** | ✅ 可持续。数据看板需要投递管理数据支撑，是投递管理的延伸 |
| **与本项目能力匹配度** | ✅ 高。前端可视化技术成熟（Chart.js、ECharts），数据来自投递管理 |
| **结论** | **做** |

#### 空白点3：多源信息聚合不足

| 维度 | 判断 |
|------|------|
| **空白是否真实** | ✅ 真实。现有产品依赖自身平台信息，缺乏跨平台聚合 |
| **空白是否可持续** | ⚠️ 不确定。技术门槛低，大平台可能跟进；但合规风险是壁垒 |
| **与本项目能力匹配度** | ✅ 高。采集技术栈已确定（Playwright+httpx），Demo阶段可控 |
| **结论** | **做**（Demo阶段），但需关注合规风险 |

### 4.2 "做/不做"清单

#### 明确要做（MVP范围）

| 功能 | 理由 |
|------|------|
| 多源采集去重 | 核心差异化，解决"信息分散"痛点 |
| 投递状态管理 | 核心差异化，解决"状态混乱"痛点 |
| 数据看板 | 核心差异化，解决"复盘困难"痛点 |
| 个性化订阅 | 增长与留存功能，解决"错过首发"痛点 |

#### 明确不做（超出MVP范围）

| 功能 | 理由 |
|------|------|
| 简历制作/优化 | 超级简历已做得很好，非本项目核心价值 |
| 面经/面试辅导 | 牛客已做得很好，非本项目核心价值 |
| 公司点评 | 看准网已做得很好，非本项目核心价值 |
| 社交/人脉 | LinkedIn已做得很好，非本项目核心价值 |
| 在线课程 | 牛客、实习僧已有，非本项目核心价值 |

### 4.3 机会判断结论

- 3个市场空白点均真实存在，且与本项目能力高度匹配
- 投递状态管理和数据看板是**可持续的差异化优势**，大平台短期内不会重点投入
- 多源信息聚合是**技术壁垒**，但合规风险需管控
- 明确"做/不做"清单，聚焦核心价值，避免功能蔓延

## 五、切入策略（GTM 雏形）

### 5.1 目标人群切入

**首批用户**：P1 林晓（高频跨平台投递者）

> **画像定义**：近一个月跨 3 个以上渠道、累计投递 20 个以上岗位的高频求职者。
> 不绑定招聘季节，任何时间点只要符合行为特征即为核心用户。

**选择理由**：
1. **痛点最强**：信息过载+状态混乱+DDL焦虑，痛点强度最高
2. **投递量大**：投递20+家，数据量大，看板价值高
3. **传播性强**：求职期间同学间交流频繁，口碑传播快
4. **投递量大才凸显投递管理价值**：P2 实习定向型投递量小，靠记忆就能管理，对工具依赖度低；P1 的海量投递才是工具价值被感知的场景

> ⏰ **路径 B 说明（v3 修订）**：
> **本项目默认采用路径 B**（与立项决策"作品集 Demo"一致）。
> 路径 B 的核心含义是：**不赶增长窗口，但必须赶验证窗口**。
> - 不赶增长窗口：Demo 的首要价值是讲清楚产品故事，不追求用户规模
> - 必须赶验证窗口：2026 秋招期间必须完成真实用户验证（见 5.4）

### 5.2 价值切入

**一句话核心价值**：
> 面向大学生的招聘信息聚合+投递管理工具，用数据看板掌握求职节奏。

**价值主张拆解**：
- **信息统一**：告别在BOSS/拉勾/牛客/实习僧/企业官网之间来回切换
- **投递闭环**：从「收藏→投递→笔试→面试→Offer/拒绝」全状态管理
- **数据驱动**：用看板看清自己的求职节奏与转化

### 5.3 渠道切入（Demo阶段）

| 渠道 | 策略 | 预期效果 |
|------|------|---------|
| **同学/朋友** | 种子用户，直接邀请体验 | 10-20人，获取初始反馈 |
| **学校就业群** | 发帖介绍工具，附截图 | 50-100人，验证需求 |
| **小红书** | 发"秋招工具分享"帖子 | 100-500人，验证传播性 |
| **牛客网** | 在求职经验板块发帖 | 50-100人，精准触达目标用户 |

### 5.4 冷启动策略

**核心问题**：没有数据就没有用户，没有用户就没有数据

**本项目的供给策略**：以目标公司池的官方校招信息为主，不依赖 UGC，也不靠违规平台抓取堆高岗位数。

> ⚠️ **路径区分（v3 修订）**：
> 冷启动策略必须区分两条路径，不能混用——
> - **路径 B（作品集 Demo，本项目默认）**：冷启动 = "采集 + 演示 + 验证"，不追求真实用户规模，但必须完成真实用户验证
> - **路径 C（若后续上线）**：才需要"种子用户 + 内容引流"的完整 GTM

#### 路径 B：作品集 Demo 的冷启动（本项目当前路径）

**目标**：让 Demo 有真实可演示的数据，能讲出完整产品故事，**不追求真实用户规模，但必须完成真实用户验证**。

**核心动作**：
1. **官方来源先行**：先建立目标公司来源注册表和 10 家技术样本，再按公司池覆盖率扩展；累计岗位数不作为首要目标
2. **数据真实化**：用真实采集的数据驱动看板（今日新增、收录总数、趋势），避免演示时被发现是假数据
3. **投递数据**：由作者本人（用户自己）真实投递 + 状态维护，作为"我用了这个工具"的一手案例
4. **演示脚本**：准备 3 个典型场景的演示动线（P1 海投/P2 订阅/P1 延伸复盘），对应 3 个画像场景

**验证窗口（v3 新增，2026 秋招期间必须完成）**：

> 作品集 Demo 可以不追求用户规模，但不能没有真实用户证据。

| 验证任务 | 数量 | 时间窗口 | 产出 |
|---------|------|---------|------|
| 目标用户访谈 | 5-8 次 | 2026 秋招期间 | 访谈记录、痛点验证、画像校准 |
| 原型可用性测试 | 3-5 次 | 2026 秋招期间 | 测试报告、交互优化建议 |
| 作者本人持续真实投递 | 持续 | 2026 秋招期间 | 一手使用案例、数据看板截图 |
| 根据反馈调整 | 持续 | 2026 秋招期间 | 画像/状态/功能优先级迭代 |

**验证窗口是阶段 2-5 的并行任务，不是阶段 6 才做**：
- 阶段 2-3（架构与设计）：并行采集 2-4 周，积累数据池；启动用户访谈
- 阶段 4（实现）：用真实数据开发，边采边迭代；进行原型可用性测试
- 阶段 5（质量收口）：准备演示脚本与作品集叙事；持续真实投递记录

**时间线（对齐阶段 2-5）**：
- 阶段 2-3（架构与设计）：并行采集 2-4 周，积累数据池
- 阶段 4（实现）：用真实数据开发，边采边迭代
- 阶段 5（质量收口）：准备演示脚本与作品集叙事
- **无"种子用户扩张"环节**——作品集面试的"用户"是面试官，不是真实注册用户

#### 路径 C：若后续决定上线的冷启动（备选，非当前路径）

## 六、风险与对策

### 6.1 合规风险

| 风险 | 等级 | 对策 |
|------|------|------|
| 采集违反平台 ToS | 高 | 逐源审核；无法确认允许时 fail closed；BOSS/猎聘无授权不抓取 |
| 数据合规（个人信息） | 高 | 不采集用户隐私数据；仅采集公开招聘信息；数据脱敏存储 |
| 版权风险 | 中 | 引用来源标注；不完整复制JD；链接跳转原平台 |

### 6.2 竞争风险

| 风险 | 等级 | 对策 |
|------|------|------|
| 大平台补投递管理功能 | 中 | 聚焦大学生垂直场景；快速迭代；建立用户习惯 |
| 新竞品进入 | 低 | 先发优势；垂直聚焦；数据积累 |
| 替代品（Excel）用户习惯 | 高 | 提供明显更好的体验；数据迁移工具；渐进式引导 |

### 6.3 技术风险

| 风险 | 等级 | 对策 |
|------|------|------|
| 来源访问或模板变化 | 高 | 固定声明身份、逐源限速、模板契约测试、连续 0 条告警和人工复核 |
| 数据源变更 | 中 | 来源注册表、解析器版本、字段完整度监控与可回退停用 |
| 数据质量（去重/清洗） | 中 | 多字段匹配去重；人工审核；用户反馈机制 |

### 6.4 产品风险

| 风险 | 等级 | 对策 |
|------|------|------|
| 用户不愿意维护状态记录 | 中 | 简化操作（一键标记）；自动化（邮件解析）；价值驱动（看板依赖状态数据） |
| 数据看板价值感知弱 | 低 | 突出"投递漏斗"核心指标；对比行业平均；提供策略建议 |
| 冷启动数据不足 | 中 | 采集先行；人工兜底；种子用户小范围验证 |

### 6.5 风险对策总结

| 风险类型 | 核心对策 |
|---------|---------|
| 合规风险 | 官方来源优先 + 逐源审核 + fail closed + 不存隐私 |
| 竞争风险 | 垂直聚焦+快速迭代+先发优势 |
| 技术风险 | 多源冗余+监控告警+人工兜底 |
| 产品风险 | 简化操作+价值驱动+渐进引导 |

## 七、总结

### 7.1 市场判断

- **值得做**：大学生求职市场基数大（855 万人量级，教育部可溯源数据），痛点真实（12 条痛点有画像支撑），竞争格局有空白（投递管理维度普遍薄弱）
- **能做**：技术栈成熟（Python+FastAPI+Next.js），以官方来源注册表和模板族适配器扩展，不依赖 UGC
- **怎么做**：聚焦 P1 秋招海投型用户，核心价值"多源聚合+投递管理+数据看板"；**作品集 Demo 走路径 B**（采集+演示，不赶时间窗，不追求真实用户规模）

### 7.2 核心结论

1. **市场空白真实存在**：投递状态管理和数据看板是现有竞品的普遍短板
2. **差异化定位清晰**：多源聚合+深度投递管理+数据看板，占据竞争定位图的空白区域
3. **切入策略可行**：从P1秋招海投型切入，冷启动"采集先行"解决鸡生蛋问题
4. **风险可控**：合规风险通过官方优先、逐源审核和受限平台禁用管控，竞争风险通过校招垂直分类与可量化覆盖应对
