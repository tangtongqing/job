## 画像选取逻辑

求职阶段与目标的不同，会导致信息需求与投递行为差异巨大。我们选取 3 个画像，覆盖**投递行为 × 生命周期**两个维度：

| 画像 | 定位 | 投递行为 | 核心矛盾 |
|------|------|---------|---------|
| P1 林晓 | **核心画像** | 高频跨平台投递 | 信息过载 vs 时间紧缺 |
| P2 周明 | **次要画像**（能力受限） | 精准定向投递 | 信息分散 vs 目标明确 |
| P3 陈晨 | **P1 延伸场景** | 复盘再投 | 状态混乱 vs 需要数据支撑 |

**画像关系说明**：
- P1 是核心画像，覆盖"近一个月跨 3 个以上渠道、累计投递 20 个以上岗位的高频求职者"
- P2 是次要画像，核心需求（首发实时推送、转正率对比）超出 MVP 能力边界，列为未来版本候选
- P3 是 P1 在秋招失败后的生命周期阶段，不作为独立核心画像，用于说明状态机复盘价值

## P1 · 林晓 —— "高频跨平台投递者"

> **画像定义**：近一个月跨 3 个以上渠道、累计投递 20 个以上岗位的高频求职者。
> 不绑定招聘季节，任何时间点只要符合行为特征即为核心用户。

### 基本信息
- **姓名**：林晓（化名）
- **身份**：985 计算机大四，正在求职
- **年龄**：22 岁
- **地点**：北京
- **目标**：互联网大厂产品/技术岗，3 个月内拿到 2-3 个 Offer

### 行为特征
- 每天浏览 BOSS / 牛客 / 拉勾 / 各厂招聘官网 ≥ 2 小时
- 同时投递 30-50 家公司，用 Excel 或备忘录记录投递状态
- 习惯在多个平台重复看到同一岗位，浪费判断时间
- 关注截止时间（网申 DDL）、笔面试时间冲突
- 收到笔试/面试邮件后，需要翻找 Excel 才能找到对应岗位

### 痛点（按强度排序）
1. **信息过载**：同一岗位多平台重复，难以判断"是否已投过"
2. **状态混乱**：Excel 记录容易遗漏更新，常忘记"这家到哪一步了"
3. **DDL 焦虑**：网申截止时间散落各处，错过重要机会
4. **复盘困难**：投了一堆，但不知道"哪类公司通过率高"，无法优化策略
5. **状态更新成本高**：收到邮件/微信后，需要打开系统翻找岗位，手填表单

### 期望功能（对应 MVP）
- 🎯 多源聚合去重 → 解决"重复信息"
- 🎯 投递状态管理 + DDL 提醒 → 解决"状态混乱 + DDL 焦虑"
- 🎯 看板（投递转化漏斗）→ 解决"复盘困难"
- 🎯 **低成本状态更新**（收到邮件/微信后，能快速记录到系统，不用打开网页翻找）→ 解决"状态更新成本高"

### 不在意
- 不需要简历优化（已有自己的简历）
- 不需要面经（牛客已满足）
- 不需要内推（有自己的渠道）

### 典型一天（场景化）
> 早上 8 点起床，打开手机刷一遍 BOSS 新岗位 → 10 点坐在电脑前，挨个打开 5 个招聘网站 → 12 点前投出 3 份简历 → 下午 2 点收到笔试邮件，翻 Excel 找"这家我投的是什么岗来着" → 晚上 11 点整理今天的投递记录，发现 2 家 DDL 已过。

### P1 的延伸场景：春招复盘（原 P3 陈晨）

> 当 P1 秋招未拿到满意 Offer 时，进入春招复盘阶段。

**新增痛点**：
1. **缺乏数据支撑**：说不清自己秋招的真实转化率，无法定位问题
2. **策略迷茫**：不知道该继续投同方向，还是换赛道
3. **心理压力大**：需要"看见进展"来维持动力

**期望功能**：
- 🎯 看板（投递漏斗、转化率）→ 解决"缺乏数据支撑"
- 🎯 投递历史回溯 → 解决"策略迷茫"
- 🎯 有效进展趋势 → 解决"心理压力"

## P2 · 周明 —— "实习定向型"（次要画像）

> ⚠️ **能力边界警示**：P2 的核心需求（首发实时推送、转正率对比）超出 MVP 能力边界，列为未来版本候选。
> 本画像用于说明"个性化订阅"功能的价值，但 MVP 阶段不作为核心用户。

### 基本信息
- **姓名**：周明（化名）
- **身份**：211 研一，找暑期实习
- **年龄**：24 岁
- **地点**：上海
- **目标**：目标公司清单明确（字节、腾讯、美团等 5-8 家），找产品实习

### 行为特征
- 只关注特定公司的特定岗位，不海投
- 习惯先收藏，观察岗位要求，再决定是否投递
- 会主动研究 JD（岗位描述）中的技能要求，对照自己查漏

### 痛点（按强度排序）
1. **信息分散**：目标公司的岗位发布在各自官网，需逐个刷新
2. **JD 难对比**：同一公司不同岗位的 JD 难以横向比较
3. **硬条件筛选缺失**：平台不标毕业年份、每周实习天数等硬条件

### 期望功能（对应 MVP）
- 🎯 个性化订阅（公司 + 岗位关键词）→ 解决"信息分散"
- 🎯 岗位详情结构化（毕业年份、学历、经验要求）→ 解决"硬条件筛选"
- 🎯 收藏 + 待投递区分 → 支持"先收藏再决策"

### 超出 MVP 能力边界的需求（未来版本）
- ❌ 首发实时推送（受采集延迟限制，无法保证"2小时招满"场景）
- ❌ 转正率对比（采集侧拿不到可靠数据）

### 不在意
- 不需要海投工具
- 不需要看板（投递量小，靠记忆够用）
- 不需要简历模板

### 典型一天（场景化）
> 每天中午和晚上各花 15 分钟，打开收藏的 6 个公司招聘页看有没有新岗 → 看到字节新发一个"产品实习生"，仔细读 JD，发现自己没有 SQL 经验 → 收藏起来，先学两天 SQL 再投 → 三天后回来想投，发现岗位已关闭。

| 功能 | P1 林晓 | P2 周明 | P3（P1延伸） | 综合优先级 |

| 岗位有效性核验 | ⭐⭐ | ⭐⭐⭐ | ⭐ | **P0** |
| 无回应关闭 | ⭐⭐⭐ | ⭐ | ⭐⭐⭐ | **P0** |
