## 一、战略选择

JobPulse 从作品集 Demo 演进为可供真实用户长期使用的个人 SaaS，定位为：

> 招聘平台之外的求职执行中心：把任何渠道发现的岗位收进来，把招聘通知变成待确认的状态与下一步行动，并保留可追溯历史。

演进原则：

1. 先保证每位用户的数据安全、可迁移、可恢复，再增加 AI、支付或团队功能；
2. 先降低开始使用和持续维护成本，再扩充岗位库与分析图表；
3. 自动化只生成建议，关键状态和日程仍由用户确认；
4. 公共岗位目录可以共享，用户的投递、收藏、订阅、通知和手工岗位必须隔离；
5. 先验证个人产品，不预先建设组织、RBAC 和团队席位。
6. 岗位供给先保证国内校招官方来源覆盖，BOSS、猎聘等平台只作为获得授权后的补充。

### 明确不做

- 完整简历制作器、通用 AI 简历改写；
- 自动海投或替用户提交外部申请；
- 社区、课程、面经与公司点评；
- 绕过登录、验证码、访问控制或反爬限制；
- 未经许可批量抓取 BOSS、猎聘等招聘平台；
- 在个人产品信号出现前建设 Team 版；
- 在持续使用和付费信号出现前接入支付。

## 三、M0：可演示（已完成）

### 用户结果

用户可以完成：

`发现岗位 → 收藏 / 待投递 → 创建投递 → 更新状态 → 形成计划事件 → 查看近期安排 → 回看历史`

### 已取得证据

- 公开演示站点和确定性演示数据可用；
- 岗位、投递、事件、通知解析、待办和采集模块形成闭环；
- 自动化测试、构建和专家模拟走查通过；
- 这些结果证明实现可行，不证明用户愿意迁移或长期使用。

### 转入 M1 的原因

作品集目标已经达到。下一阶段不再以“页面是否可演示”为完成标准，而以真实用户是否能安全开始、持续使用和离开产品为标准。

## 四、M0.5：建立国内校招官方供给基础

### 结果陈述

> 让目标公司池中的秋招、春招、暑期实习、日常实习和补录信息从企业官方来源进入系统，完整收录其公开的全部校招岗位，并让覆盖缺口可见。

### 结果指标

| 指标 | 试点退出标准 |
|---|---:|
| 海外默认实时来源 | 0 个启用 |
| 试点公司官方入口登记 | 100% |
| 人工审计样本中的官方活动发现率 | ≥95% |
| 招聘高峰期发现延迟 | P95 ≤24 小时 |
| 官方链接保留 | 100% |
| 招聘季/实习类型/届别确认 | ≥90%，无法确认时明确标记 |

### 候选输出

- 目标公司池与 `CompanySourceRegistry`；
- 招聘活动、正式公告、岗位和来源证据分层；
- 秋招、春招、暑期实习、日常实习、补录和多毕业届别分类；
- 企业自建站及 Moka、北森、用友大易等模板族适配器；
- 政府/高校就业平台发现、公众号链接收录和人工复核队列；
- 来源健康、覆盖率、发现延迟和待复核缺口看板。

### 退出条件

- 首批 10 家技术样本端到端通过，再扩展到 100 家公司池；
- 10 家样本官方职位页的公开校招岗位 100% 对账到入库、隔离或带原因失败记录；
- 海外或纯社招内容不会进入默认校招目录和订阅；
- BOSS、猎聘等无授权来源保持关闭；
- 覆盖率口径明确限定在目标公司池，不对外使用“全网 100%”表述。

## 五、M1.0：让真实用户可以安全使用

### 结果陈述

> 让个人求职者拥有独立、可导出、可删除且可恢复的数据，使 JobPulse 具备邀请真实用户的最低安全条件。

### 结果指标

| 指标 | 退出标准 |
|---|---:|
| 未认证访问私人 API | 100% 被拒绝 |
| 跨用户读取或修改 | 0 条成功路径 |
| 业务数据归属 | 100% 的私人对象可追溯到用户 |
| 数据导出完整度 | 核心对象和关系 100% 可导出 |
| 删除流程 | 用户可发起；在线主库在承诺窗口内完成删除 |
| 备份恢复 | 至少完成一次隔离环境恢复演练 |
| Demo 与生产数据 | 数据库、重置权限和环境配置完全隔离 |

### 候选输出

- 登录、会话和用户模型；
- PostgreSQL、正式迁移历史和恢复脚本；
- 私人对象 `user_id` 数据归属；
- 生产环境关闭 Demo 重置和匿名写操作；
- 数据导出、账号删除、隐私与授权记录；
- 错误监控、审计日志、健康检查和最小产品事件。

### 退出条件

- 安全与数据隔离测试通过；
- SQLite 演示数据可迁移到 PostgreSQL，迁移可回退；
- 备份恢复、导出和删除均有可复现记录；
- 才能邀请第一批真实账号。

## 六、M1.1：让用户能低成本开始

### 结果陈述

> 让已有 Excel、Notion 或零散记录的求职者在较短时间内建立第一个可用工作区，降低迁移和重复录入阻力。

### 结果指标

| 指标 | 研究目标 |
|---|---:|
| 固定模板有效行导入成功率 | ≥95% |
| 单行失败可解释率 | 100% |
| 首次进入到拥有一个真实投递 | 中位数 ≤10 分钟 |
| 核心迁移任务完成率 | 至少 4/5 参与者独立完成 |
| 导入幂等性 | 重复提交不产生重复投递 |

### 候选输出

- CSV 模板、预览、字段校验、逐行错误与确认导入；
- CSV/JSON 导出；
- “求职收件箱”：接受岗位 URL、招聘通知文本和最小手工信息；
- 未匹配内容先生成待确认草稿，不直接污染业务数据；
- 从公开岗位 URL 提取可确认的公司、岗位、JD、来源和截止时间；
- 新用户引导只围绕“导入一条或收进一条”，不要求配置完整资料。

### 退出条件

- 完成 3–5 次目标用户任务测试；
- 迁移阻塞项关闭；
- 新用户不依赖演示数据也能建立真实工作区。

---

## 七、M1.2：让用户每天知道下一步

### 结果陈述

> 让进行中的求职者每天能快速看清即将截止、面试、测评、跟进和待确认事项，减少遗漏而不是增加维护负担。

### 结果指标

| 指标 | 研究目标 |
|---|---:|
| 已创建提醒的系统送达率 | ≥99%（排除用户关闭权限） |
| “今天”页面任务找回率 | 至少 4/5 参与者独立找到指定任务 |
| 明确时间写入准确率 | ≥90%，低置信度必须确认 |
| 7 天维护持续性 | 试用者中至少 60% 在 3 天以上记录真实进展 |
| 订阅价值 | 用户能收到匹配结果，而不只是保存规则 |

### 候选输出

- “今天”作为登录后的默认入口；
- 截止、面试、测评、跟进、无回应和待确认建议统一排序；
- 站内提醒与浏览器/PWA 通知；
- 订阅规则匹配、去重、已读和通知记录；
- 提醒重试、失败可见和时区处理；
- 看板降为复盘入口，不占据每日主任务首位。

### 退出条件

- 完成真实提醒端到端测试；
- 至少完成一轮 7 天真实使用；
- 证明提醒和今日行动比原有工具组合更省步骤。

---

## 八、M1.3：让系统减少跨工具搬运

### 结果陈述

> 让用户在外部岗位页和招聘沟通到来时，用更少操作更新 JobPulse，同时保留人工确认和撤权能力。

### 推荐顺序

1. 浏览器扩展：保存允许访问的公开岗位页字段、投递后确认建档；BOSS/猎聘无授权时只保存 URL 并手工补字段；
2. 邮件转发入口：用户主动转发单封招聘邮件，避免一开始申请全邮箱权限；
3. 邮箱授权：仅在用户明确接受权限、转发方案证明有价值后建设；
4. 日历：先支持 ICS 导出，再评估 Google/Outlook 双向同步。

### 结果指标

| 指标 | 研究目标 |
|---|---:|
| 支持页面的一键收集成功率 | ≥90% |
| 招聘通知匹配到正确投递 | ≥90%，未达阈值只进入待确认 |
| 自动建议被正确理解 | 无参与者误以为系统已自动执行 |
| 外部集成撤权 | 用户可自行断开，断开后立即停止新增同步 |
| 原始敏感文本 | 默认不进入产品分析事件或普通日志 |

### 退出条件

- 扩展、邮件或日历任一渠道证明显著降低步骤；
- 权限说明、撤权、数据保留和删除路径通过检查；
- 无明确价值的集成不继续扩展。

---

## 九、M1.4：验证商业价值

### 结果陈述

> 让持续使用者能够为节省的时间、可靠提醒或自动化额度付费，同时保持免费层核心闭环可用。

### 进入条件

- 真实用户能连续使用，而非只完成一次演示；
- 同步、通知和数据托管成本已经可测量；
- 至少出现主动询价、请求更多额度或明确付费意愿；
- 隐私、安全、退款和降级方案已经准备。

### 候选实验

- Free：核心记录、基础提醒和数据导出；
- Pro：更多自动化额度、邮件/日历集成和高级提醒；
- 用价格访谈、假门测试或限量付费内测验证，不直接沿用旧版 ¥29 假设；
- 支付接入排在价值和价格验证之后。

### 退出条件

- 定价有真实研究或交易证据；
- 套餐限制不会破坏用户取回和删除自己数据的权利；
- 付费、取消、退款、到期和降级均可测试。

## 十、M2 可选方向

以下均不是承诺，只在 M1 数据支持时评估：

| 方向 | 启动信号 |
|---|---|
| 团队 / 导师协作 | 求职辅导机构或导师持续提出共享需求 |
| 原生移动端 | 移动端使用占比高，且 Web/PWA 阻塞核心任务 |
| 更深简历能力 | 简历版本关联被高频使用，并出现明确的定向优化需求 |
| 更广岗位目录 | 官方来源可持续、数据新鲜度能稳定达到承诺 |

## 十一、跨阶段健康指标

所有阶段共同跟踪：

- 激活：首次真实岗位或投递建立；
- 维护：7 天内有实际状态、计划或收件箱确认行为；
- 行动：提醒被查看、完成或合理忽略；
- 自动化：建议准确率、确认率、拒绝率和纠错率；
- 信任：导出、删除、撤权、隐私投诉和跨用户访问；
- 可靠性：API 错误率、任务积压、提醒失败和备份恢复；
- 研究边界：演示数据、专家走查和真人行为始终分开统计。
