# P0 闭环缺口：范围、实施与验证

**状态**：已完成
**完成日期**：2026-07-28
**范围**：JobPulse 产品端
**明确排除**：营销页、案例页、CSV/Notion 导入、订阅通知

## 研究依据

[公开情景研究与角色模拟走查](../research/online-scenario-role-walkthrough-2026-07-28.md) 暴露了两个会破坏核心闭环的缺口：

1. 招聘通知中的面试/测评时间没有进入近期安排；
2. 岗位库之外的外部投递无法进入统一时间线。

研究样本来自公开求职记录与边界明确的专家模拟角色，是设计输入，不是真人可用性测试。

## 用户任务与验收标准

### 任务 A：从通知到行动

用户粘贴招聘邮件或聊天通知，系统提取公司、岗位、建议状态和明确时间。用户确认后：

- 状态完成合法流转；
- 面试或测评时间写入计划事件；
- 详情时间线与近期安排读取同一事件；
- 未确认的解析结果不改状态、不写事件。

验收标准：

- 正则降级和 LLM 路径都能返回 `interview_time`；
- `interviewing + interview_time` 创建 `interview` 待办；
- `test + interview_time` 创建 `test` 待办；
- 不支持计划事件的状态携带时间时被拒绝；
- 状态事件与计划事件在同一事务中写入，失败时整体回滚。

### 任务 B：记录岗位库外投递

用户完成外部渠道投递后，可用公司和岗位两个必填字段补录；地点、原始链接、投递日期和备注为可选。

验收标准：

- 一次提交原子创建手动岗位、投递和初始 `applied` 事件；
- 创建后进入投递详情，并继续使用现有状态机与时间线；
- 手动岗位使用 `source=manual`；
- 同一手动岗位已有进行中投递时返回冲突；
- 任一步失败时不留下孤立岗位或事件。

## 实施

1. 扩展 AI 解析结构、提示词和正则时间提取；
2. 扩展解析接口、确认接口和前端结果展示；
3. 在单条状态确认事务中写入状态事件与计划事件；
4. 增加外部投递请求模型和原子创建接口；
5. 在投递管理页增加内联补录表单；
6. 补充解析、事务、时间线、待办、字段校验与重复投递测试。

没有新增数据库表；实现复用了 `Job`、`Application` 与 `ApplicationEvent`。批量状态流转语义保持不变，解析建议不会自动执行。

## 结果

| 阶段 | 结果 |
|---|---|
| 通知时间 → 计划事件 | 已贯通解析、确认、事务、详情和近期安排 |
| 外部岗位 → 正式投递 | 已完成原子接口与投递页内联表单 |
| 自动化与浏览器复测 | 120 项后端测试、前端 lint/build 与隔离角色路径通过 |
| 完整矩阵 | 核心 19/23、边界 1/3、全部 20/26 |

`19/23` 和 `20/26` 是专家模拟走查的结果覆盖，不是用户任务完成率。

## 剩余非 P0 缺口

- Excel / Notion 历史投递导入；
- 从未知招聘通知自动创建全新投递；
- 实习天数与实习周期字段；
- 订阅通知发送闭环；
- 按公司、岗位方向或来源的细分转化分析。
