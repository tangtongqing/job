# 可信岗位采集：研究、实施与结果

**状态**：M0 历史专项已完成；其海外默认来源已于 2026-08-05 停用
**适用范围**：公开 ATS 岗位采集、确定性 Demo 快照、来源与字段质量展示

> 本文记录 M0 如何验证公开 ATS 采集链路，不再指导 M1 的岗位供给。M1 改为国内校招官方来源优先，见[国内校招数据源策略](../product/DATA-SOURCE-STRATEGY.md)；Greenhouse 代码保留，但 Figma、Webflow、Intercom、Stripe 不再默认启用。

## 背景与目标

早期 JobPulse 可以演示投递管理，但采集层字段不完整，也无法清楚区分演示数据和真实采集。本专项的目标是：

- 有足够数量的岗位用于稳定演示；
- 保留完整 JD、任职要求、官方来源页和投递链接；
- 证明真实采集链路可运行；
- 不登录、不处理验证码、不绕过反爬；
- 断网时仍能使用明确标记的确定性演示快照。

长期个人使用所需的账号、云同步、邮件/移动推送不属于本专项。

## 方案比较与决策

| 方案 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 公开 ATS API + 演示快照 | 字段完整、官方链接真实、无需登录、可离线演示 | 需要规范化和字段提取 | 采用 |
| 逐家企业官网 HTML 适配 | 国内公司覆盖更好 | 结构不统一、动态渲染和维护成本高 | 暂不采用 |
| 只扩充本地种子数据 | 稳定、开发快 | 不能证明采集链路真实可用 | 仅作为快照层 |

核心决策：

1. 新增通用 `GreenhouseAdapter`，由同一套代码配置 Figma、Webflow、Intercom 和 Stripe。
2. 单源只保留产品、设计、研究、数据与增长相关岗位，限制数量以控制演示规模。
3. 将 JD HTML 转为纯文本，尽可能结构化要求、薪资、学历、经验、发布时间和截止时间。
4. 保留 ATS 返回的官方 `apply_url` 与 `source_url`。
5. 公开 API 失败时记录失败，不删除已有岗位、不破坏 Demo。
6. BOSS、牛客等需登录或有访问控制的平台保持禁用。

## 非功能约束

- 单源单次最多保留 15 个相关岗位；
- 超时 20 秒，最多重试 2 次；
- 不存储求职者数据，不代替用户提交申请；
- 采集管理页必须展示来源状态、Demo/Live 数量与字段完整度；
- 旧的伪“采集成功”日志改为明确的演示初始化记录。

## 实施结果

### 公开 ATS 采集

- 完成可复用 Greenhouse Job Board API 适配器；
- 四个来源独立配置但复用适配器；
- YAML 配置支持标准列表；
- 补充适配器、配置、过滤、规范化和去重测试。

### 确定性演示数据

- 快照扩展到 24 条完整岗位；
- 补齐 JD、要求、官方链接、学历、经验和核验元数据；
- 使用 `demo_snapshot` 明确标记来源；
- 重置后核心详情字段与外链覆盖率为 100%。

### 质量可见性

- 增加来源状态和字段完整度 API；
- 采集页展示启用来源、Demo/Live 数量、质量指标和真实日志；
- 岗位列表/详情统一显示来源、演示声明和官方申请动作。

## 验证基线

专项验收时的数据集为 56 条岗位（24 Demo + 32 公开 API）：

| 指标 | 结果 |
|---|---|
| 完整 JD | 100% |
| 官方投递链接 | 100% |
| 官方来源链接 | 100% |
| 结构化要求 | 98% |
| 后端测试 | 107 项通过（专项完成时） |
| 前端 | ESLint 通过，14 路由生产构建通过 |

后续项目基线已继续提升，当前值以 [验收报告](../qa/ACCEPTANCE-REPORT.md) 为准。
